# The COBOL editor for Visual Studio (2026-11-22)

**Result: built and tested inside Visual Studio 2022. In 2026 the colors and guides were
checked by screenshot only.** `dist\CobolDotNet.Editor.vsix` installs into Visual Studio
2022 and 2026 (Community, Professional, Enterprise). Opening a `.cbl`, `.cob` or `.cpy` file
then gives:

- **Syntax colors** from the compiler's own word list (`cobc --list-reserved`, 1,003 words
  with aliases, plus 115 intrinsic functions):
  - keywords, comments (`*`/`/` in column 7, and `*>`), literals (including `X"41"`), numbers;
  - picture strings (`PIC $$$,$$9.99`);
  - paragraph and section names in **bold** where they're defined;
  - the sequence number (columns 1-6) and the identification area (73-80) in gray.

  All of these can be changed in Tools > Options > Environment > Fonts and Colors
  ("COBOL ...").
- **Column guides** for fixed format:
  - a light band over columns 1-6 and 73+;
  - a line where area A starts (column 8) and a dotted line at area B (column 12);
  - a reddish line after column 72.

  Free-format files get none of these.
- **Sequence numbers kept the Wang way** (decision of 2026-11-22). The numbers always read
  000010, 000020, ... by tens:

  | Key | What happens |
  |---|---|
  | Enter at the end of a line | New line numbered +10, indented under the code above (or into area B after a paragraph name); every line below moves up 10 |
  | Enter in mid-line | Splits; the rest keeps its indent |
  | Enter at column 8 | Opens a line above |
  | Backspace at column 8 | Joins the line onto the one above; the lines below close up by 10 |
  | Backspace just after a `*` | Removes the indicator (uncomments the line) |
  | Delete at the end of a line | Joins the next line on |
  | Delete or typing in columns 1-6 | The number isn't typed over; typed text goes to column 8 |
  | Typing `*` `/` `-` `D` in column 7 | Sets the indicator |
  | Tab | Spaces to the next stop: column 8, 12, 16, ... |
  | Home | To the first character of code, then to column 8 |
  | Paste, Cut, Duplicate line, Move line up/down, Open line above/below | Run normally, then renumber |
  | Anything else that adds or removes lines (Find and Replace, drag and drop) | Renumbered right after |

  Each keystroke is **one undo step**, number changes included.

  Only files that already have numbers (first line starts with 6 digits) are numbered
  automatically. **Edit > Renumber COBOL Lines** (also on the right-click menu, shown only in
  COBOL files) numbers a file that has none, or repairs one.

## Pieces

| File | What it does |
|---|---|
| `editor/CobolDotNet.Editor/Core/CobolScanner.cs` | splits a line into colored tokens (no VS types) |
| `editor/CobolDotNet.Editor/Core/SequenceNumbers.cs` | the numbering rules as plans: what each key changes and where the caret goes (no VS types) |
| `editor/CobolDotNet.Editor/Core/CobolWords.cs` | generated by `tools/make-editor-words.ps1` from our cobc |
| `CobolContentType.cs` | the COBOL content type, `.cbl/.cob/.cpy`, color definitions |
| `CobolClassifier.cs` | colors, via the scanner |
| `ColumnGuides.cs` | the adornment layer with the bands and lines |
| `SequenceNumberCommands.cs` | editor command handlers (Enter, Backspace, ...), the one-undo-step wrapper, and the watcher for other edits |
| `CobolEditorPackage.cs` + `CobolEditor.vsct` | the Renumber command, made visible by a UI-context rule (`ActiveEditorContentType:COBOL`) |
| `editor/CobolDotNet.Editor.Tests` | 76 headless tests of the scanner and the numbering rules |
| `editor/vs-test/` | the in-Visual-Studio test (22 checks) |

Build: `tools\build-editor.ps1` (logic tests, then the VSIX with Visual Studio's MSBuild). The
project is SDK-style, targets net472, and references `Microsoft.VisualStudio.SDK` 17.0 (so it
loads in 17.x and 18.x) and `Microsoft.VSSDK.BuildTools` 17.14. That package doesn't import its
targets by itself, so the csproj imports `Microsoft.VsSDK.targets` after the .NET SDK targets.

## Verified

- **Headless:** 76 tests (`dotnet run --project editor\CobolDotNet.Editor.Tests`). Every sample
  renumbers back to itself from blank columns 1-6. Each key plan, and the scanner on each kind
  of token, is tested too.
- **Inside Visual Studio 2022** (experimental instance, `editor\vs-test\run-vs-test.ps1`):
  - The test drives the real editor through DTE commands, with no keystrokes. 22 of 22 pass:
    Enter (end, mid-line), Backspace and Delete joins, Tab, Home twice, Duplicate line, an
    automation edit renumbered by the watcher, and Renumber on an unnumbered file.
  - Undo after each one restores the file in one step.
  - Screenshots show the colors and guides.
- **Visual Studio 2026:** installed into its experimental instance. A screenshot shows the
  colors and guides working. The keystroke test didn't run there: VS 2026 opened an Account
  Settings window about an expired sign-in, which blocks automation. The user has to deal
  with that window; I didn't touch it.

**Not verified:** typing in columns 1-7, and Paste and Cut inside VS. DTE can't type, and
paste would overwrite the user's clipboard. Their logic is in the headless tests.

## Known gaps (next)

- **Watch window** still shows `f_17` rather than `WS-PAY` (debugger display layer).
- **No IntelliSense or outlining.** Commenting via Ctrl+K, Ctrl+C isn't wired up either.
- **A license** for the extension (the user's call, see DECISIONS.md). `LICENSE.txt` is a
  placeholder.
- **The templates and the editor ship separately.** One installer that puts both, plus the
  SDK feed, on a learner's PC is still to come.
