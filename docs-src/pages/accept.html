Syntax

Format 1: read a line of input
ACCEPT identifier-1
[ END-ACCEPT ]

Format 2: the date and time
ACCEPT identifier-1 FROM { DATE [ YYYYMMDD ] | DAY [ YYYYDDD ] | DAY-OF-WEEK | TIME }
[ END-ACCEPT ]

Format 3: the command line and the environment
ACCEPT identifier-1 FROM { COMMAND-LINE | ARGUMENT-NUMBER | ARGUMENT-VALUE
                         | ENVIRONMENT literal-1 | ENVIRONMENT-VALUE }
    [ ON EXCEPTION imperative-statement-1 ]
    [ NOT ON EXCEPTION imperative-statement-2 ]
[ END-ACCEPT ]

Format 4: a field on the screen (see SCREEN SECTION)
ACCEPT { identifier-1 AT LINE line-number COL column-number | screen-name }
[ END-ACCEPT ]

What it does

ACCEPT puts a value into a data item from outside the program. Where the value comes from depends on the format.

Reading input (Format 1)

Plain ACCEPT identifier reads one line from standard input: what the user types at the keyboard, or a file fed to the program with < on the command line. The line is then moved into the field the way MOVE would:

  • Into an alphanumeric field (PIC X), text is placed from the left. A short line is padded with spaces; a long one is cut off on the right.
  • Into a numeric field, the text is read as a number, so you can type 12.5 or -42 and the decimal point and sign go where the PICTURE says.
  • When there is no more input (end of file), an alphanumeric field is filled with spaces.

Nothing you type is shown by the program itself; the console echoes it as you type. To print a prompt on the same line as the answer, use DISPLAY ... WITH NO ADVANCING first.

Use the four-digit-year forms in new programs. For more control (time zone, formatting) use the intrinsic functions such as FUNCTION CURRENT-DATE.

Command line and environment (Format 3)

  • COMMAND-LINE: everything typed after the program's name, as one string.
  • ARGUMENT-NUMBER: how many arguments there are.
  • ARGUMENT-VALUE: the next argument, one per ACCEPT. ON EXCEPTION runs when there are no more.
  • ENVIRONMENT "NAME": the value of environment variable NAME. ON EXCEPTION runs when it isn't set, and the field is filled with spaces.
  • ENVIRONMENT-VALUE: the value of the variable named earlier by DISPLAY "NAME" UPON ENVIRONMENT-NAME.

A program can set a variable for itself (and the programs it starts) with SET ENVIRONMENT "NAME" TO value; see SET.

Screens (Format 4)

With AT LINE ... COL ..., or with the name of a screen from the SCREEN SECTION, ACCEPT lets the user type into fields on a full screen instead of reading a line. That is covered on the SCREEN SECTION page.

Examples

Reading lines of input

The prompt and the name appear on one line because of WITH NO ADVANCING (the typed text isn't part of the output here, because it came from a file). 7 and 12.5 become numbers with leading zeros, -42 keeps its sign, and TOOLONGTEXT is cut to the five characters SHORT-CODE holds. The last ACCEPT finds no more input, so LEFT-OVER becomes spaces.

Date and time

The program checks each value instead of printing it, so its output is the same every day. In your own programs you would simply DISPLAY TODAY-8. NOW-TIME is a group, so its parts can be used one by one after a single ACCEPT.

Arguments and environment variables

The program was run with no arguments, so ARGUMENT-NUMBER is 0 and the command line is blank. ACCEPT3_MODE was set by the program itself just before it was read. ACCEPT3_NOT_SET doesn't exist, so the exception branch runs and the field is cleared to spaces.

Look at the END-DISPLAY after the first DISPLAY. Without it, the NOT ON EXCEPTION line would belong to that DISPLAY, not to the ACCEPT, because DISPLAY has exception phrases of its own; both messages would print. Close any statement that could take the next phrase with its END- word.

SP COBOL notes

Plain ACCEPT, the date and time forms, and the command-line and environment forms behave as in GnuCOBOL 3.2. The screen form follows SP COBOL's screen rules, which differ from GnuCOBOL in a few ways meant for beginners (the first key typed replaces a field's contents, for example); see SCREEN SECTION.
