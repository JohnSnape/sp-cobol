title: ADD summary: Add numbers together and store the sum. keywords: TO GIVING ROUNDED SIZE ERROR END-ADD CORRESPONDING CORR sum plus addition ---

Syntax

Format 1: add to each receiving field
ADD { identifier-1 | literal-1 } ... TO { identifier-2 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-ADD ]

Format 2: store the sum somewhere else
ADD { identifier-1 | literal-1 } ... [ TO { identifier-2 | literal-2 } ]
    GIVING { identifier-3 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-ADD ]

Format 3: add matching fields of two groups
ADD { CORRESPONDING | CORR } group-1 TO group-2 [ ROUNDED ]
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-ADD ]

What it does

Format 1 adds every value before TO together, then adds that total to each field after TO. The fields after TO change; the ones before it don't. ADD A B TO C means "C = C + A + B".

Format 2 adds up all the values (the ones after TO too) and puts the sum in the field after GIVING, replacing what was there. Nothing else changes. ADD A TO B GIVING C means "C = A + B". Because the GIVING field only receives the answer, it may be a numeric-edited field such as PIC $$,$$9.99.

Format 3 adds each numeric item of the first group to the item with the same name in the second group. Items whose names have no match are skipped.

Decimals and rounding

COBOL lines up the decimal points for you. If the answer has more decimal places than the receiving field can hold, the extra digits are dropped (truncated), unless you write ROUNDED after that field.

SIZE ERROR

If the answer has more digits in front of the decimal point than the receiving field can hold, that's a size error. Without ON SIZE ERROR, the high-order digits are lost silently: adding 5 to a PIC 9 holding 7 leaves 2. With ON SIZE ERROR, the field keeps its old value and your statements run instead. NOT ON SIZE ERROR runs when the answer fit.

Write END-ADD when the ADD has a SIZE ERROR phrase and sits inside an IF or another statement, so it's clear where the phrase ends.

Example

The first ADD adds 19.95 and 4.50 to TOTAL, which started at zero. The second replaces TOTAL with 19.95 + 4.50. ROUGH has one decimal place, so 24.45 is rounded to 24.5. The fourth would make TINY 12, which doesn't fit in PIC 9, so TINY keeps its value and the SIZE ERROR message is shown. The last ADD has no SIZE ERROR phrase, so the leading 1 of 12 is simply lost and TINY becomes 2.
