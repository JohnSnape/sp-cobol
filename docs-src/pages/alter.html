Syntax

ALTER procedure-name-1 TO [ PROCEED TO ] procedure-name-2
    [ procedure-name-3 TO [ PROCEED TO ] procedure-name-4 ] ...

What it does

ALTER changes the target of a GO TO while the program is running. procedure-name-1 must be a paragraph that holds nothing but one GO TO sentence. After the ALTER, that GO TO jumps to procedure-name-2 instead of where its source code says.

It was used in early COBOL as a switch: "the first time through, go here; after that, go there". The example below shows the classic pattern.

Why not to use it

ALTER was declared obsolete in the 1985 standard and removed from the 2002 standard. The problem is that the source code no longer tells the truth: GO TO FIRST-TIME may really go somewhere else, and the only way to know is to find every ALTER that names the paragraph and work out which ones have run. Programs that use it are very hard to read, test and change. You will meet it only in old code.

Use a flag (a data item, usually with an 88-level condition name) and an IF or EVALUATE instead. The decision is then written where it happens.

Examples

The classic ALTER switch

GREET through GREET-EXIT is performed three times. The first time, GREET's GO TO FIRST-TIME goes where it says: the welcome prints, and the ALTER changes GREET so that from then on it goes to LATER-TIMES. The second and third times print "WELCOME BACK", although the source line still reads GO TO FIRST-TIME.

The better way: a flag

The same "first time only" greeting, written with a flag instead of ALTER:

GREET is performed three times. The first time the flag is still "Y", so the welcome prints and the flag is turned off; after that the ELSE branch runs. The output is the same as the ALTER version, and the decision can be read straight from the code.
