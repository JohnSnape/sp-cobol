title: CANCEL summary: Reset a called program, so that the next CALL starts it with fresh WORKING-STORAGE. keywords: CANCEL CALL subprogram WORKING-STORAGE reset IS INITIAL INITIAL program fresh state ---

Syntax

CANCEL { literal-1 | identifier-1 } ...

What it does

A called program keeps its WORKING-STORAGE between calls. If a subprogram counts how often it has been called, the count goes on growing from one CALL to the next, because its data stays in memory after GOBACK.

CANCEL throws that state away. The next CALL to the program finds it as if for the first time: every WORKING-STORAGE item is back to its VALUE clause (or to its default if it has none). Name the program the same way as in CALL: a literal or a data item holding the PROGRAM-ID. You can cancel several programs in one statement. Cancelling a program that hasn't been called yet does nothing.

IS INITIAL programs

If a program should always start fresh, write IS INITIAL in its PROGRAM-ID paragraph: PROGRAM-ID. TAXCALC IS INITIAL. Its WORKING-STORAGE is reset on every CALL, with no CANCEL needed.

Example

The first CANCEL names a program that hasn't run yet, which is allowed and does nothing. CANCELSUB1 counts 1, 2 across the first two calls. After CANCEL "CANCELSUB1" its CALL-COUNT is back to its VALUE of 0, so the third call prints 1 again. CANCELSUB2 is an INITIAL program, so it prints 1 on every call without being cancelled.
