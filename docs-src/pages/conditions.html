Syntax

Relation condition:
operand-1 [ IS ] [ NOT ] { =  | EQUAL TO
                         | >  | GREATER THAN
                         | <  | LESS THAN
                         | >= | GREATER THAN OR EQUAL TO
                         | <= | LESS THAN OR EQUAL TO
                         | <> } operand-2

Class condition:
identifier [ IS ] [ NOT ] { NUMERIC | ALPHABETIC | ALPHABETIC-UPPER
                          | ALPHABETIC-LOWER | class-name }

Sign condition:
identifier [ IS ] [ NOT ] { POSITIVE | NEGATIVE | ZERO }

Condition name:
condition-name

Combined and negated:
condition-1 { AND | OR } condition-2 ...

What it does

A condition is a test that is either true or false. Conditions appear in IF, EVALUATE, PERFORM ... UNTIL and SEARCH ... WHEN.

Relation conditions

Compare two values. The symbols and the words mean the same: A < B is A IS LESS THAN B. NOT reverses the test, so A NOT = B is true when they differ (<> says the same thing).

  • Numbers are compared by value, whatever their pictures: PIC 9(3) holding 005 equals PIC 9V99 holding 5.00.
  • Text is compared character by character from the left, by the characters' codes. If the two sides are different lengths, the shorter one is treated as if padded with spaces on the right. So a PIC X(8) field holding "ADA" equals the literal "ADA", and the same rule makes IF NAME = SPACES true for an all-blank field of any length.
  • Either side may be an arithmetic expression: IF A + 1 > B * 2. Both sides may even be literals (IF 1 < 2), though such a test always gives the same answer.
  • A figurative constant such as HIGH-VALUES, SPACES or ALL "*" is repeated to the length of the other side, so IF KEY-FIELD = HIGH-VALUES is true only when every byte of KEY-FIELD is a high value.

Class conditions

Test what kind of characters an item holds:

TestTrue when
NUMERICEvery character is a digit (a numeric item may also have a valid sign). Use it to check input before doing arithmetic with it.
ALPHABETICEvery character is a letter (upper or lower case) or a space.
ALPHABETIC-UPPEREvery character is A-Z or a space.
ALPHABETIC-LOWEREvery character is a-z or a space.
class-nameEvery character is in a CLASS you defined in SPECIAL-NAMES, such as CLASS HEX-DIGIT IS "0" THRU "9" "A" THRU "F".

Spaces count as alphabetic, so a blank field passes ALPHABETIC.

Sign conditions

POSITIVE is true for a value greater than zero, NEGATIVE for less than zero, and ZERO for exactly zero. Zero is neither positive nor negative. The item tested may be an arithmetic expression: IF BAL + 12 IS ZERO.

Condition names

A level 88 entry gives a name to one or more values of an item; the name itself is a condition: IF IS-MEMBER. See condition names.

AND, OR, NOT and parentheses

Join conditions with AND (both must be true) and OR (at least one must be true). NOT in front of a condition reverses it. Without parentheses, NOT is applied first, then AND, then OR, so A AND B OR C means (A AND B) OR C. Use parentheses whenever you mix AND and OR; they cost nothing and say what you mean.

Abbreviated combined conditions

When several relations test the same item, you can leave the item out after the first: IF CODE-X = 1 OR 3 OR 5 means IF CODE-X = 1 OR CODE-X = 3 OR CODE-X = 5, and IF AGE > 12 AND < 20 means IF AGE > 12 AND AGE < 20. The left side and the last operator written carry forward to each value that follows.

IF A NOT = 1 OR 2 means A NOT = 1 OR A NOT = 2, which is always true. To test "A is neither 1 nor 2" write IF NOT (A = 1 OR A = 2), or use an 88-level name.

Example: relation, class and sign conditions

FIRST-NAME is eight characters holding "ADA" and five spaces; compared with the three-character literal "ADA", the literal is padded with spaces, so they are equal. "ADA" is less than "BOB" because A comes before B, and greater than "AD" because the padded "AD " has a space where "ADA" has an A. "12A" is not NUMERIC, but its first two characters are. FIRST-NAME is ALPHABETIC and ALPHABETIC-UPPER because its trailing spaces count as alphabetic.

Example: combined conditions

AGE > 12 AND < 20 and CODE-X = 1 OR 3 OR 5 are the abbreviated forms. In the last two IFs, CODE-X is 3, so CODE-X = 9 is false. Without parentheses the test is (CODE-X = 9 AND AGE = 99) OR IS-MEMBER, which is true because of IS-MEMBER. With the parentheses, the AND needs CODE-X = 9, so the whole test is false.

Example: numbers by value, and the NOT trap

WHOLE and WITH-CENTS have different pictures but the same value, so they are equal. A NOT = 1 OR 2 expands to A NOT = 1 OR A NOT = 2; A is 1, so the second half is true and the whole test passes. The version with parentheses says what was meant.

Example: expressions, literals, a CLASS and HIGH-VALUES

11 is more than 8, and -12 + 12 is zero, so the first two tests are true. 1 < 2 compares two literals and is always true. HEX-DIGIT is a class defined in SPECIAL-NAMES: every character of "1F3A" is in it, but the G in "1G3A" is not. LAST-KEY was filled with HIGH-VALUES, so it equals them, and any ordinary text compares less than HIGH-VALUES.
