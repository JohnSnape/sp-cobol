Syntax

Format 1: debugging lines (compiled only in debugging mode)
SOURCE-COMPUTER. computer-name WITH DEBUGGING MODE.
      D    statement ...                  (D in column 7)

Format 2: Watch window expressions (Visual Studio)
DATA_NAME                 a data item, with _ for each -
DATA_NAME[n]              occurrence n of a table
COBOL                     every 01 and 77 item
COBOL["data-name"]        any item by its COBOL name

What it does

A bug is a mistake that makes a program do the wrong thing. There are three kinds of help for finding one: the compiler's and runtime's error messages, Visual Studio's debugger, which lets you stop the program and look inside it, and extra DISPLAY statements that print what the program is doing as it runs.

Error messages

When a program doesn't compile, Visual Studio's Error List shows each message with its COBOL file and line; double-click one to jump there. For the mistakes beginners make most often, the message ends with a plain-English hint after --, for example a syntax error suggests checking for a missing period, a misspelled word or code that starts before column 8.

When a running program stops with a fatal error (a file that isn't there, a CALL of a program that doesn't exist), the runtime prints GnuCOBOL's message and then a line starting hint: that says what to check. Set the environment variable COB_NO_HINTS=1 to turn the hint lines off.

The Visual Studio debugger

Press F5 to run the program under the debugger. Click in the margin next to a COBOL line to set a breakpoint: the program stops just before that line runs. Then step through the program one COBOL line at a time with Visual Studio's usual Step Over (F10) and Step Into (F11) commands. The Call Stack window shows the names of the paragraphs and sections being performed, because each paragraph becomes a method in the program SP COBOL builds.

The Watch window

While the program is stopped, type a data item's name into the Watch window to see its value. Write it in the debugger's style: - becomes _, so WS-PAY is WS_PAY. The value is shown the way DISPLAY would show it, and the Type column shows the item's PICTURE and USAGE. For the example program below:

WatchShows
WS_PAY0712.50, type PIC 9(4)V99
WS_TOTALits value, type PIC S9(7)V99 COMP-3
CUSTOMERthe whole group; expand it to see CUST-NAME and CUST-CITY
MONTH_ENTRY[2]occurrence 2 of the table (expand MONTH_ENTRY to see them all)
COBOLevery 01 and 77 item of the program
COBOL["ws-pay"]any item by its COBOL name, in upper or lower case

Some things to know:

  • An item inside a table, such as MONTH_SALES, shows its first occurrence. Use the table's [n] for the others.
  • If two items have the same name (in different groups, the ones you'd qualify with OF), only the first gets a Watch name. Reach the others by expanding their group, or through COBOL.
  • LINKAGE SECTION items show "(no data ...)" until the program has been CALLed.
  • Not shown: elementary FILLER items, level 66 (RENAMES), 88 (condition names) and 78 (constants), special registers such as RETURN-CODE, COB-CRT-STATUS, EXTERNAL items, LOCAL-STORAGE items and ANY LENGTH items. To see a condition name, watch the item it belongs to.

Debugging lines

A line with D in column 7 is a debugging line. It's compiled only when the SOURCE-COMPUTER paragraph says WITH DEBUGGING MODE; otherwise it's treated as a comment. That lets you leave tracing DISPLAYs in a program and switch them all on or off by changing one line.

Tracing with DISPLAY

The oldest way to debug still works everywhere: add DISPLAY statements that show where the program is and what its key fields hold, such as DISPLAY "IN CALC-PAY: HOURS=" WS-HOURS. Put square brackets around text fields (DISPLAY "[" WS-NAME "]") to see trailing spaces.

Debugging lines

With WITH DEBUGGING MODE the D line runs and traces each pass of the loop. Remove those three words and the program prints only the TOTAL line.

A runtime error with a hint

The file doesn't exist, so OPEN INPUT fails with status 35 and the program stops with exit code 1. The first message is GnuCOBOL's; the hint: line after it is SP COBOL's, and names the folder the program looked in (here, the folder the example was run in).

SP COBOL notes

Differs from GnuCOBOL 3.2: stock GnuCOBOL prints only the libcob: error line, without the hint. Its message also names the file as 'customers_dat' => customers.dat (the last environment variable it looked up); SP COBOL names it as written in ASSIGN.
USE FOR DEBUGGING declaratives (which fill in DEBUG-ITEM) don't work in SP COBOL yet: the program fails to build. Use debugging lines with DISPLAY instead.
