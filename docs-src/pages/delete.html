Syntax

Format 1: delete a record
DELETE file-name [ RECORD ]
    [ INVALID KEY imperative-statement-1 ]
    [ NOT INVALID KEY imperative-statement-2 ]
[ END-DELETE ]

Format 2: delete files from the disk
DELETE FILE file-name-1 ...

What it does

Format 1 removes one record from a RELATIVE or INDEXED file. (Records can't be removed from SEQUENTIAL or LINE SEQUENTIAL files; copy the file without them instead.) Like READ, it takes the file name. The file must be open I-O (status 49 otherwise).

  • With sequential access, it deletes the record the last READ returned; a READ must come just before (status 43 otherwise).
  • With random or dynamic access, it deletes the record whose key you set: the slot number in the RELATIVE KEY, or the value in the RECORD KEY. If there is no such record, the status is 23 and INVALID KEY runs.

A deleted RELATIVE slot becomes empty: reading in order skips it, and a later WRITE can fill it again.

Format 2, DELETE FILE, erases the file from the disk. The file must be closed. Deleting a file that doesn't exist gives status 35.

Example

Task 2 is deleted. There is no task 7, so the second DELETE takes the INVALID KEY branch with status 23. Reading from slot 1 on shows only tasks 1 and 3. Finally DELETE FILE removes tasks.dat, and opening it for input gives 35.

SP COBOL notes

DELETE of an empty RELATIVE slot that lies inside the file gives 23 in SP COBOL; GnuCOBOL 3.2 reports 00, a bug in its file handler. See REWRITE for the same difference shown in an example.

The format of SP COBOL's indexed files doesn't reuse the space of deleted records; it stays in the file until the file is copied (see Files).
