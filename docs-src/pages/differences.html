SP COBOL uses GnuCOBOL 3.2's compiler front end, and its runtime is written to give the same results as GnuCOBOL's: a test suite runs every sample program under both and compares the output and the data files byte for byte. So a program that works with GnuCOBOL 3.2 should work the same way with SP COBOL, and the other way round.

The exceptions are listed here. Each one is deliberate: either GnuCOBOL has a plain bug, or its behavior would only confuse someone learning COBOL, or the COBOL standard says otherwise. Features neither of them supports are on Not supported.

Kept on purpose, although surprising

These GnuCOBOL 3.2 behaviors look odd, but SP COBOL keeps them so that programs give the same results in both:

  • Report Writer: PRESENT WHEN on a single field never prints the field (Report Writer). On a LINE it works.
  • UNSTRING into a JUSTIFIED RIGHT item fills it from the left (UNSTRING). MOVE does justify.
  • XML and JSON GENERATE output only the first occurrence of an OCCURS item, put the raw bytes of a number into an XML attribute (-123.45 becomes 001234u), and stop the program on COMP-1 / COMP-2 items (XML GENERATE, JSON GENERATE).
  • A READ after the end of a file gives status 46, and goes to a USE AFTER ERROR procedure even when the READ has an AT END phrase (USE).
  • Files: lines end with CR LF on Windows; CLOSE ... REEL gives status 07; a LINAGE file pads pages with blank lines, not form feeds; an "implicit CLOSE" warning appears when STOP RUN finds a file still open; the program ends with exit code 1 after a fatal file error (Files).
  • DISPLAY of a COMP-5 item shows as many digits as its size can hold (5 for 2 bytes, 10 for 4, 20 for 8), whatever its PICTURE says (USAGE).
  • Intrinsic functions: TEST-NUMVAL-C rejects a currency string longer than one character; EXCEPTION-FILE treats any exception in the 05xx group as a file error; short negative UTC offsets print as +00mm; COMBINED-DATETIME overflows for very large day numbers; SECONDS-PAST-MIDNIGHT ignores COB_CURRENT_DATE (Intrinsic functions).
  • Not implemented in either: PROCEDURE DIVISION RETURNING and the intrinsic functions listed on Not supported.
