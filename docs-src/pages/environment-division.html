Syntax

ENVIRONMENT DIVISION.
[ CONFIGURATION SECTION.
  [ SOURCE-COMPUTER. computer-name [ WITH DEBUGGING MODE ]. ]
  [ OBJECT-COMPUTER. computer-name
        [ PROGRAM COLLATING SEQUENCE IS alphabet-name ]. ]
  [ SPECIAL-NAMES.
        [ CRT STATUS IS data-name-1 ]
        [ CURSOR IS data-name-2 ]
        [ CURRENCY SIGN IS literal-1 ]
        [ DECIMAL-POINT IS COMMA ]
        [ CLASS class-name IS { literal-2 [ THRU literal-3 ] } ... ]
        [ ALPHABET alphabet-name IS
              { NATIVE | STANDARD-1 | EBCDIC | { literal-4 [ THRU literal-5 ] } ... } ]
        [ SYMBOLIC CHARACTERS { symbol-name ... { IS | ARE } integer ... } ... ]
        . ] ]
[ INPUT-OUTPUT SECTION.
  FILE-CONTROL.
      SELECT file-name ASSIGN TO { literal-6 | data-name-3 }
          [ ORGANIZATION IS { LINE SEQUENTIAL | SEQUENTIAL | RELATIVE | INDEXED } ]
          [ other-file-clauses ] . ... ]

What it does

The ENVIRONMENT DIVISION holds the parts of a program that depend on the machine it runs on and the files it uses. A program that uses no files and no special names can leave the whole division out.

CONFIGURATION SECTION

SOURCE-COMPUTER and OBJECT-COMPUTER name the computer the program is compiled on and runs on. The names are documentation only. One phrase matters: SOURCE-COMPUTER. name WITH DEBUGGING MODE. turns on the debugging lines (D in column 7, see source format). PROGRAM COLLATING SEQUENCE in OBJECT-COMPUTER names an ALPHABET that sets the order used when the program compares text.

SPECIAL-NAMES gives names to things the program needs:

ClauseWhat it does
CRT STATUS IS itemAfter an ACCEPT of a screen, item (a PIC 9(4) field) holds the key that ended the input: 0 for Enter, 1001 for F1, 2005 for Esc, and so on. See SCREEN SECTION.
CURSOR IS itemNames a field holding a screen position (line and column) for the cursor. See SP COBOL notes.
CURRENCY SIGN IS "c"Uses a different character instead of $ as the currency symbol in PICTURE strings (see SP COBOL notes).
DECIMAL-POINT IS COMMASwaps the roles of period and comma, the European way: 1234,50 is a number with two decimals, and PICTURE Z.ZZ9,99 is meant to print 1.234,50 (see SP COBOL notes).
CLASS name IS ...Defines your own class condition: a list of the characters allowed, such as "0" THRU "9" "A" THRU "F". Then IF field IS name is true when every character of the field is in the list (see SP COBOL notes).
ALPHABET name IS ...Names a character order: NATIVE (the machine's own), STANDARD-1 (ASCII), EBCDIC (the IBM mainframe order) or a list of literals in the order you want. It is meant for PROGRAM COLLATING SEQUENCE and the COLLATING SEQUENCE phrase of SORT (see SP COBOL notes).
SYMBOLIC CHARACTERS name IS nGives a name to a single character by its position in the character set. Positions count from 1, so the character with code 42 (*) is position 43. The name can then be used like a one-character literal.

The clauses of SPECIAL-NAMES are written one after another, and a single period ends the whole paragraph.

INPUT-OUTPUT SECTION

The FILE-CONTROL paragraph has one SELECT entry for each file the program uses. SELECT gives the file the name the program uses for it, ASSIGN TO says which file on disk it is, and ORGANIZATION says how its records are laid out. Each file also needs an FD entry in the FILE SECTION of the DATA DIVISION. The details (ACCESS MODE, RECORD KEY, FILE STATUS, ...) are on the files page.

Example: SYMBOLIC CHARACTERS

Position 43 is * (code 42) and position 46 is - (code 45). STAR and DASH can be used anywhere a one-character literal could.

Example: FILE-CONTROL

The SELECT connects the name NAME-FILE to the disk file NAMES.TXT, a line sequential (plain text) file. The program writes two lines, then reads the first one back.

Example: CRT STATUS

The keystrokes typed "ADA", Tab, "LOVELACE" and then F1. F1 ended the ACCEPT, so KEY-CODE holds 1001.

SP COBOL notes

Several SPECIAL-NAMES clauses compile but don't work yet in this preview:
  • CLASS: a program that tests a user-defined class doesn't build.
  • ALPHABET: a program that uses an alphabet, in PROGRAM COLLATING SEQUENCE or in the COLLATING SEQUENCE phrase of a SORT, doesn't build.
  • DECIMAL-POINT IS COMMA: the numbers themselves are right, but MOVE to an edited picture (such as Z.ZZ9,99) prints the wrong digits.
  • CURRENCY SIGN: an edited picture using the new sign prints the wrong result.
  • CURSOR IS: accepted, but the cursor position is not used; input always starts at the first field.
Until they are fixed, test characters with INSPECT or a loop, keep the standard period and $ in pictures, and order the fields on a screen so the first one is where input should begin.
