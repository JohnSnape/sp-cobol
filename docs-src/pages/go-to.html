title: GO TO summary: Jump to another paragraph or section, without coming back. keywords: GO TO GOTO jump branch DEPENDING ON computed goto PERFORM THRU exit paragraph spaghetti structured programming ---

Syntax

Format 1
GO TO procedure-name-1

Format 2
GO TO { procedure-name-1 } ... DEPENDING ON identifier-1

What it does

GO TO sends the program to the start of another paragraph or section. Unlike PERFORM, it doesn't come back: the program simply carries on from the new place, and falls into the paragraphs that follow it in the source.

Format 2 picks a target by number. GO TO P-ONE P-TWO P-THREE DEPENDING ON K goes to P-ONE when K is 1, P-TWO when K is 2, and P-THREE when K is 3. For any other value of K (zero, negative, or more than the number of names) nothing happens and the next statement runs. K must be an integer.

When you will see it

GO TO was the main way to control the flow of early COBOL programs. Today it survives mostly in one pattern: a PERFORM PARA THRU PARA-EXIT range where GO TO PARA-EXIT leaves early, and the exit paragraph holds only EXIT. A GO TO that stays inside the range being performed is safe.

Why structured code avoids it

A program full of GO TOs is hard to follow, because to know how you reached a paragraph you have to search for every GO TO that names it. A GO TO that jumps out of a PERFORMed range can also leave the PERFORM unfinished, which causes confusing bugs later. Modern COBOL has a structured way to do each job:

  • loops: PERFORM ... UNTIL and PERFORM VARYING
  • choices: IF and EVALUATE (which also replaces GO TO DEPENDING ON)
  • leaving early: EXIT PARAGRAPH, EXIT SECTION, EXIT PERFORM

Example

The loop performs PICK THRU PICK-EXIT four times. For K = 1, 2 and 3, GO TO DEPENDING ON jumps to P-ONE, P-TWO or P-THREE. Each of those jumps on to PICK-EXIT (P-THREE just falls into it, since it comes next). For K = 4 there is no fourth name, so the statement after the GO TO runs. After the loop, a plain GO TO moves to FINISH, which ends the run.
