title: IDENTIFICATION DIVISION summary: Name the program, and optionally mark it COMMON, INITIAL or RECURSIVE. keywords: PROGRAM-ID AUTHOR INSTALLATION DATE-WRITTEN DATE-COMPILED SECURITY COMMON INITIAL RECURSIVE program name ---

Syntax

IDENTIFICATION DIVISION.
PROGRAM-ID. program-name [ IS { COMMON | INITIAL | RECURSIVE } ].
[ AUTHOR. comment-entry ]
[ INSTALLATION. comment-entry ]
[ DATE-WRITTEN. comment-entry ]
[ DATE-COMPILED. comment-entry ]
[ SECURITY. comment-entry ]

What it does

The IDENTIFICATION DIVISION comes first in every program. Its one required entry is PROGRAM-ID, which gives the program its name. The name is what other programs use in CALL, and what END PROGRAM repeats. Use letters, digits and hyphens.

Comment paragraphs

AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED and SECURITY are left over from early COBOL. The compiler reads the text after each one as a comment, up to the next paragraph, so they change nothing about the program. Many shops still fill them in as a standard header. Today a block of * comment lines does the same job.

COMMON

Normally a nested program can be called only by the program that directly contains it. IS COMMON lets its sibling nested programs (the others inside the same outer program) call it too. That makes it a good place for a helper every part of the outer program uses.

INITIAL

A called program normally keeps its WORKING-STORAGE from one CALL to the next: a counter that was 2 when the program last returned is still 2 next time. IS INITIAL makes the program start fresh each time it is called, with every item back at its VALUE.

RECURSIVE

IS RECURSIVE allows a program to CALL itself, directly or through another program. Without it, a program that is already running may not be called again until it returns. Each active call of a recursive program needs its own copy of its working items, so put them in the LOCAL-STORAGE SECTION (see DATA DIVISION), which is set up fresh on every call; WORKING-STORAGE is shared by all the calls. A program with LOCAL-STORAGE can't be nested inside another, so a recursive program is usually a separate program, as in the third example.

Example: the comment paragraphs

The five paragraphs after PROGRAM-ID are only comments; the program just runs its one DISPLAY.

Example: COMMON and INITIAL

IDDIV2KEEP is an ordinary program, so CALLS-SEEN keeps counting: 1, 2, 3. IDDIV2INIT is INITIAL, so its CALLS-SEEN goes back to 0 on every CALL and always shows 1. IDDIV2SHOW is COMMON, which is why IDDIV2KEEP, its sibling, may call it.

Example: a RECURSIVE program

IDDIV3FACT works out a factorial: N! is N times (N - 1)!, and 1! is 1. For any N above 1 it CALLs itself with N - 1, then multiplies the answer it gets back by N. SMALLER and SUB-ANSWER are in LOCAL-STORAGE, so each level of the call has its own pair, and a deeper call can't overwrite the values of the call waiting for it. IDDIV3FACT follows END PROGRAM IDDIV3 in the same file, so it is a separate program, not a nested one.
