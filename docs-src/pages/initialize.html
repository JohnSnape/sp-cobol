title: INITIALIZE summary: Reset the fields of a group, record or table: spaces in text fields, zeros in numeric ones. keywords: INITIALIZE REPLACING ALPHANUMERIC NUMERIC NUMERIC-EDITED ALPHANUMERIC-EDITED WITH FILLER ALL TO VALUE THEN TO DEFAULT clear reset blank zero record table ---

Syntax

INITIALIZE identifier-1 ...
    [ WITH FILLER ]
    [ { ALL | category } TO VALUE ]
    [ REPLACING { category [ DATA ] BY { identifier-2 | literal-1 } } ... ]
    [ THEN TO DEFAULT ]

category:  { ALPHABETIC | ALPHANUMERIC | ALPHANUMERIC-EDITED | NUMERIC
           | NUMERIC-EDITED | NATIONAL | NATIONAL-EDITED }

What it does

INITIALIZE sets every elementary item inside identifier-1 to a starting value chosen by its category. On its own, with no phrases:

Kind of fieldBecomes
alphabetic, alphanumeric, alphanumeric-edited (PIC A, X)spaces
numeric (PIC 9, any USAGE)zero
numeric-edited (PIC ZZ9.99, $$$9.99)zero, edited through its PICTURE

FILLER items are left alone unless you write WITH FILLER. Every occurrence of a table (OCCURS) is initialized. You can also name a single elementary field.

INITIALIZE is clearer than MOVE SPACES TO record, which also blanks the numeric fields, leaving them invalid for arithmetic.

The phrases

  • REPLACING category BY value: fields of that category get value, moved as by MOVE. Fields of the categories you don't name are not changed (add THEN TO DEFAULT to give them spaces and zeros). A numeric-edited field is not NUMERIC for this purpose; name NUMERIC-EDITED to replace it.
  • WITH FILLER: initialize FILLER items too.
  • ALL TO VALUE: fields that have a VALUE clause get that value back. Fields without one are not changed.
  • THEN TO DEFAULT: after the other phrases, fields they didn't set get the usual space or zero.
The standard says NUMERIC TO VALUE (a category instead of ALL) restores only the VALUE clauses of that category. GnuCOBOL 3.2, and SP COBOL with it, restores the VALUE clauses of every category either way, so write ALL TO VALUE and avoid the surprise.

Examples

With REPLACING, the alphanumeric field gets "?" (padded with spaces, as a MOVE would) and the numeric ones 7. CUST-SHOW is numeric-edited, a category the REPLACING phrase doesn't name, so it keeps $12.00. The plain INITIALIZE then blanks CUST-NAME, zeros the numeric fields, and gives CUST-SHOW the edited form of zero. INITIALIZE works on a single field as well. In the table, all three occurrences get spaces and zeros.

FILLER, VALUE and DEFAULT

PART-REC has a FILLER holding "-*-". A plain INITIALIZE leaves the FILLER alone; WITH FILLER blanks it too. ALL TO VALUE puts back the VALUE clauses of PART-CODE and PART-QTY, but not the FILLER's, since FILLER was not included this time; PART-NOTE has no VALUE and is not touched. The last statement, after the record was filled with X's, restores every VALUE (FILLER included) and then gives PART-NOTE, which has no VALUE, its default of spaces.
