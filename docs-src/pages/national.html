Syntax

level-number data-name PIC N(n) [ USAGE [ IS ] NATIONAL ] [ VALUE N"text" ] .

A national literal
N"text"

What it does

National data holds Unicode characters, so it can store text in any language. Each N in the PICTURE is one character, kept as UTF-16: two bytes per character, high byte first. PIC N(5) holds five characters in 10 bytes. FUNCTION LENGTH counts characters; FUNCTION BYTE-LENGTH counts bytes.

A literal written N"..." is a national literal. Use it in VALUE clauses, MOVEs and comparisons with national items. MOVE and comparison work as with PIC X: a longer value is cut on the right, and two national items compare character by character.

USAGE NATIONAL

PIC N is national by itself, so you don't need to write USAGE NATIONAL.

In GnuCOBOL 3.2, adding USAGE NATIONAL to a PIC N item doubles its size again: PIC N(5) USAGE NATIONAL is 20 bytes, not 10, and a 5-character value moved into it is followed by 5 characters of padding. SP COBOL lays out storage exactly as GnuCOBOL does, so it does the same. Leave USAGE NATIONAL out.

Padding

When a shorter national value is moved into a national item, GnuCOBOL fills the rest with bytes of hexadecimal 20 (the single-byte space), two per character, rather than with the Unicode space. A DISPLAY in SP COBOL shows each such pair as ? (see the next section). Keep national values the full length of the item, or pad them yourself, if you plan to DISPLAY them.

DISPLAY of national data

A DISPLAY of a PIC N item in SP COBOL prints its characters. Characters above U+00FF can't be shown on the console, which uses the Latin-1 character set, so each prints as ?.

SP COBOL notes

SP COBOL deliberately differs here. GnuCOBOL 3.2's DISPLAY writes a national item's raw UTF-16 bytes, so N"HELLO" prints as NUL H NUL E NUL L NUL L NUL O, which is no use to a reader. SP COBOL decodes the field and prints the characters (above U+00FF as ?), on the console and on SCREEN SECTION screens. The storage is unchanged, so MOVEs, comparisons and data files are the same as in GnuCOBOL. Only what DISPLAY prints is different; that is why this example's output is not compared with GnuCOBOL's.

The compiler warns that national support is "unfinished" in GnuCOBOL. That warning is about GnuCOBOL's own runtime; SP COBOL's project builds turn it off.

The intrinsic functions NATIONAL-OF and DISPLAY-OF are not implemented in GnuCOBOL 3.2's runtime, and stop the program in SP COBOL too.
