title: OPEN summary: Open one or more files for reading, writing, updating or adding to the end. keywords: INPUT OUTPUT I-O EXTEND OPTIONAL open file create file replace append 35 41 05 ---

Syntax

OPEN { { INPUT | OUTPUT | I-O | EXTEND } file-name-1 ... } ...

What it does

A file must be opened before any READ, WRITE, REWRITE, DELETE or START, and the open mode decides which of those you may use:

ModeWhat it's forIf the file doesn't existIf it exists
INPUTReading only. Reading starts at the first record. Status 35 (or 05 for an OPTIONAL file)Left as it is
OUTPUTWriting a new file.Created Emptied: the old records are gone
I-OReading and changing records (REWRITE, DELETE, and WRITE for RELATIVE and INDEXED files).Status 35Left as it is
EXTENDAdding records after the last one.Status 35 New records go after the old ones

One OPEN can open several files, and can mix modes: OPEN INPUT OLD-MASTER TRANSACTIONS OUTPUT NEW-MASTER. It does the same as separate OPENs, one after another.

The FILE STATUS after OPEN is 00 when it worked. Opening a file that is already open gives 41, and leaves it open as it was. Opening a file that was closed WITH LOCK gives 38.

OPTIONAL files

A file declared SELECT OPTIONAL is allowed to be missing. OPEN INPUT of a missing optional file succeeds with status 05, and the first READ is at end (status 10). This suits files such as "yesterday's errors" that may or may not be there.

Example

The first OPEN opens two files for output at once. OPEN EXTEND then adds a second line to open-a.txt, while OPEN OUTPUT on open-b.txt throws its old line away, so only "B NEW" is left. The optional file open-c.txt was never created: OPEN gives 05 and the READ gives 10.

OPEN OUTPUT on an existing file empties it without asking. When a program should add to a file, use EXTEND (or I-O); when it should create a file only if there is none, try OPEN INPUT first and look for status 35.
