Syntax

PROCEDURE DIVISION [ USING { [ BY REFERENCE | BY VALUE ] data-name-1 } ... ] .
[ DECLARATIVES.
  { section-name SECTION.
        USE-statement .
    [ paragraph-name. [ sentence ] ... ] ... } ...
  END DECLARATIVES. ]
{ [ section-name SECTION. ]
  { paragraph-name.
        [ sentence ] ... } ... } ...

What it does

The PROCEDURE DIVISION is where the program does its work. It is made of paragraphs, which may be grouped into sections (see program structure). Statements before the first paragraph name are allowed too, as in many short examples on this site.

How control flows

The program starts at the first statement of the PROCEDURE DIVISION (after any DECLARATIVES) and runs downward. When it reaches the end of a paragraph it simply carries on into the next paragraph: a paragraph name is a label, not a wall. This is called falling through. The order changes only when a statement changes it:

  • PERFORM runs a paragraph or section (or a range with THRU) and comes back to the statement after the PERFORM.
  • GO TO jumps to a paragraph and doesn't come back.
  • STOP RUN ends the run; GOBACK returns to the caller (or ends the run in the main program).

Running off the end of the last paragraph ends the program as GOBACK would. The usual pattern is a main paragraph at the top that PERFORMs the others and ends with STOP RUN or GOBACK, so control never falls into the paragraphs below by accident.

USING: receiving parameters

A subprogram lists the items it receives from its caller after USING. Each one must be described in the LINKAGE SECTION. They are matched to the caller's CALL ... USING list by position, not by name. BY REFERENCE (the default) means the subprogram works directly on the caller's item, so changes are seen by the caller. The details, including BY CONTENT and BY VALUE, are on the CALL page.

RETURNING

PROCEDURE DIVISION RETURNING is not supported, the same as in GnuCOBOL 3.2: the compiler warns "program RETURNING is not implemented". To pass a result back, set RETURN-CODE in the subprogram (the caller reads it after the CALL, or receives it with CALL ... RETURNING), or change an item the caller passed BY REFERENCE. The second example below does both.

DECLARATIVES

If present, DECLARATIVES come first, between DECLARATIVES. and END DECLARATIVES. Each section in them starts with a USE statement saying when it runs, for example after an error on a file. These sections are not reached by falling through; the run time calls them when their event happens.

Example: falling through

FIRST-PARA performs THIRD-PARA, which runs and comes back. Then FIRST-PARA ends and control falls into SECOND-PARA, then into THIRD-PARA again. After the last paragraph there is nothing more, so the program ends. There is no STOP RUN anywhere.

Example: USING and RETURN-CODE

PROCDIV2SQ receives NUM and SQUARE by reference. It stores the square straight into the caller's SQUARE and reports success in RETURN-CODE. 200 squared (40000) doesn't fit in PIC 9(4), so the SIZE ERROR phrase sets RETURN-CODE to 8. The main program clears RETURN-CODE before STOP RUN, since its value becomes the program's exit code.
