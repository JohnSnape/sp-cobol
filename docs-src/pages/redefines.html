title: REDEFINES summary: Describe the same bytes of storage a second way. keywords: REDEFINES overlay union two views same storage date year month day ---

Syntax

level-number data-name-1 REDEFINES data-name-2 [ other clauses ] .

What it does

REDEFINES doesn't create new storage. It gives the bytes of data-name-2 a second description, data-name-1. Both names refer to the same memory, so a change through one name is seen through the other at once.

The most common uses are:

  • splitting a value into parts, such as a date PIC 9(8) seen as year, month and day;
  • looking at the same bytes as text or as a number, for example to check input before using it in arithmetic;
  • starting a table with different values: FILLER items with VALUEs, redefined as an OCCURS table (see VALUE);
  • records that come in several layouts, where a type code says which layout applies.

Rules

  • The REDEFINES entry has the same level number as the item it redefines, and comes right after it (after that item's own subordinate items, if it is a group).
  • You can redefine an item more than once: several entries can all name the same data-name-2.
  • At level 01 the new description may be longer than the original, as in the example. At lower levels keep it the same size or shorter.
  • Don't put a VALUE on the redefining item; give the starting value on the original.

COBOL doesn't convert anything between the two views. If the bytes don't make sense for the new description, such as letters seen through a PIC 9 item, you get nonsense rather than an error.

Example

TODAY-PARTS covers the same 8 bytes as TODAY, so YYYY, MM and DD show the parts of the date. Moving 12 to MM changes the month inside TODAY. AMOUNT-9 sees the six characters 001250 as the number 12.50; adding 1 to it changes the text to 001350. LONG-ONE is a 6-byte view of a 4-byte item, which is allowed at level 01.
