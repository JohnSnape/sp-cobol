title: REWRITE summary: Replace a record that is already in a file with a changed version. keywords: REWRITE FROM INVALID KEY NOT INVALID KEY END-REWRITE update record in place I-O 43 49 23 badge: differs ---

Syntax

REWRITE record-name [ FROM { identifier-1 | literal-1 } ]
    [ INVALID KEY imperative-statement-1 ]
    [ NOT INVALID KEY imperative-statement-2 ]
[ END-REWRITE ]

What it does

REWRITE puts a changed record back in the place of an existing one. The file must be open I-O (status 49 otherwise). FROM item moves item to the record first, as with WRITE.

Which record is replaced depends on the access mode:

  • Sequential access (all SEQUENTIAL and LINE SEQUENTIAL files): the record the last READ returned. The pattern is READ, change fields, REWRITE. Without a successful READ just before, the status is 43. In a SEQUENTIAL file the record must keep its length.
  • Random or dynamic access: the record with the key you set, the slot number in the RELATIVE KEY or the value in the RECORD KEY. No READ is needed first. If there is no such record, the status is 23 and INVALID KEY runs.

For an INDEXED file the RECORD KEY in the record says which record is replaced, so to change a record's key, DELETE it and WRITE a new one. Alternate key fields may be changed by REWRITE.

SP COBOL notes

REWRITE of an empty RELATIVE slot gives 23 (record not found) in SP COBOL. GnuCOBOL 3.2 reports 00 and even writes the record into the empty slot, which is a bug in its file handler. That's why the second example's output differs from GnuCOBOL's.

When a LINE SEQUENTIAL record is rewritten with a shorter one, SP COBOL keeps the line end intact; GnuCOBOL 3.2 overwrites the CR in that case.
