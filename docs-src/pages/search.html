title: SEARCH summary: Look through a table for an entry that meets a condition. keywords: SEARCH ALL AT END WHEN VARYING END-SEARCH INDEXED BY ASCENDING KEY DESCENDING binary search lookup table find ---

Syntax

Format 1: serial search, entry by entry
SEARCH identifier-1 [ VARYING { identifier-2 | index-name-1 } ]
    [ AT END imperative-statement-1 ]
    { WHEN condition-1 { imperative-statement-2 | NEXT SENTENCE } } ...
[ END-SEARCH ]

Format 2: binary search of a sorted table
SEARCH ALL identifier-1
    [ AT END imperative-statement-1 ]
    WHEN key-condition [ AND key-condition ] ...
        { imperative-statement-2 | NEXT SENTENCE }
[ END-SEARCH ]

where key-condition is:
    data-name-1 [ ( index-name ) ] { IS EQUAL TO | IS = } { identifier-3 | literal-1 }
  | condition-name-1

What it does

SEARCH looks through a table, an item defined with OCCURS, for an entry that matches a condition. identifier-1 is the item that has the OCCURS clause, and it must also have an INDEXED BY clause: SEARCH moves that index from entry to entry. An index is a special counter for a table; you set it and change it with SET, and use it as a subscript, as in COLOR-NAME (CX).

Serial SEARCH

The plain SEARCH starts at the entry the index points to now, so you normally write SET CX TO 1 just before it. For each entry it checks the WHEN conditions in order. When one is true, its statements run and the SEARCH ends, with the index left pointing at the entry that matched. If the index runs past the last entry without a match, the AT END statements run instead (or, without AT END, the program just carries on after the SEARCH).

You may write several WHEN phrases, and any kind of condition; the first one that is true wins.

VARYING names a second item that SEARCH moves along with the index. If it is a numeric item, it ends up holding the same entry number as the index.

SEARCH ALL

SEARCH ALL finds an entry much faster in a large table by doing a binary search: it looks at the middle entry, decides which half the wanted entry must be in, and repeats. For that to work:

  • the table must have an ASCENDING KEY (or DESCENDING KEY) clause naming the field it is sorted on, and the entries must really be in that order;
  • the WHEN condition may only test key fields for equality (=), joined with AND, and the key must be subscripted with the table's first index;
  • there is only one WHEN.

SEARCH ALL sets the index itself, so you don't SET it first. If the table is not in key order, SEARCH ALL can miss entries that are there; it doesn't check the order for you.

Examples

LOOK-UP sets the index to 1 and searches. BLUE is the third entry, so the WHEN runs and SET POSITION-NO TO CX copies the entry number out of the index. PINK isn't in the table, so AT END runs. The last SEARCH starts at entry 2 instead of 1 and finds YELLOW at entry 4; STEP-COUNT, the VARYING item, holds that entry number too.

The table of states is in order of the two-letter code, which the ASCENDING KEY clause declares. SEARCH ALL finds NV and shows its name. TX isn't there, so AT END runs.
