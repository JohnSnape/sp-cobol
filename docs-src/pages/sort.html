Syntax

Format 1: sort records
SORT sort-file-name
    { ON { ASCENDING | DESCENDING } KEY data-name-1 ... } ...
    [ WITH DUPLICATES IN ORDER ]
    [ COLLATING SEQUENCE IS alphabet-name ]
    { USING file-name-1 ... | INPUT PROCEDURE IS procedure-1 [ { THRU | THROUGH } procedure-2 ] }
    { GIVING file-name-2 ... | OUTPUT PROCEDURE IS procedure-3 [ { THRU | THROUGH } procedure-4 ] }

Format 2: sort a table in memory
SORT table-name
    { ON { ASCENDING | DESCENDING } KEY data-name-2 ... } ...

What it does

Sorting records

Format 1 sorts records through a sort file. You declare it like an ordinary file, with a SELECT, but describe it with SD (sort description) instead of FD. Its record lists the fields the records are sorted by. You never OPEN, READ or WRITE the sort file yourself; SORT does that.

The KEY phrases give the sort keys, most important first. ON ASCENDING KEY W-TEAM ON DESCENDING KEY W-GOALS means "by team A to Z, and within a team by goals, highest first". Numeric keys are compared by value (so -4 comes before 19); other keys character by character.

The records come in one of two ways:

  • USING file: SORT opens the file, reads every record and closes it. The file must not be open.
  • INPUT PROCEDURE IS para: SORT performs your paragraph (or section), which hands each record over with RELEASE. Use it to pick or change records on the way in, or to sort data that isn't in a file.

And go out in one of two ways:

  • GIVING file: SORT writes the sorted records to a new file (it is opened OUTPUT, so an existing one is replaced).
  • OUTPUT PROCEDURE IS para: SORT performs your paragraph, which takes the records one at a time in order with RETURN, for counting, totals, or a report.

Records with equal keys come out in the order they went in. WITH DUPLICATES IN ORDER asks for exactly that.

After the SORT, the special register SORT-RETURN is 0 if it worked and 16 if it failed.

Sorting a table

Format 2 sorts the entries of a table (an item with OCCURS) in place. Name the OCCURS item, and give keys that are fields inside each entry. No SD or file is involved.

The input procedure releases four records taken from a table; the output procedure returns them warmest first. W-TEMP is a signed number, so -04 sorts below +19.

Equal keys

Three records have the key A1 and two have B2. Within each key they come out in the order they were released (2, 4, 6 and 1, 5).

SP COBOL notes

SP COBOL sorts in memory, without work files, so the file named in the sort file's ASSIGN is never created. That suits the record counts of learning and business programs; a file too big for memory can't be sorted.

Table SORT keeps equal entries in order; GnuCOBOL's may not. GnuCOBOL sorts tables with the C library's qsort, which may shuffle entries that have equal keys, and the result can vary between systems. SP COBOL's table sort is stable: entries with equal keys keep their order. The two agree whenever the keys are all different, as in the example above. If the order of equal entries matters to you, add a second key that tells them apart.

COLLATING SEQUENCE IS alphabet-name on SORT and MERGE doesn't work in SP COBOL yet: a program that uses it with an ALPHABET (EBCDIC or one you define) fails to build, because the alphabet's table isn't translated to C#. Sort with the default (ASCII) order.
