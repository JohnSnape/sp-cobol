Syntax

Columns  1-6    7          8-11     12-72    73-80
         000010 indicator  area A   area B   ignored

Indicator (column 7):
  space   an ordinary line
  *       comment line
  /       comment line that starts a new page in a printed listing
  -       continuation of the line above
  D       debugging line (compiled only WITH DEBUGGING MODE)

Floating comment, anywhere from column 7 on:
  *> comment-text

What it does

COBOL was written on 80-column punched cards, and fixed-format source still keeps their layout. Each column range of a line has a job:

ColumnsNameWhat goes there
1-6sequence number areaA line number: 000010, 000020, ...
7indicator areaBlank, or one of * / - D (below).
8-11area AThings that begin a new part of the program: division, section and paragraph names, FD/SD, level numbers 01 and 77, END PROGRAM, DECLARATIVES.
12-72area BEverything else: statements, the level numbers 02-49, 66 and 88, clauses that continue a line.
73-80identification areaIgnored by the compiler. On cards it held the program's name.

In practice: start division, section and paragraph names and 01 levels in column 8, and start statements in column 12. Anything you type after column 72 is not part of your program, which can cause confusing errors when a long line gets cut off. Keep lines short and continue statements on the next line instead; a statement can be split between any two words.

Sequence numbers

Columns 1-6 hold a line number. SP COBOL's convention is to number from 000010 in steps of 10 (000010, 000020, 000030, ...), the way COBOL is usually written, and every example on this site follows it. The compiler ignores these columns completely: a gap, a duplicate or a line out of order is never an error.

The COBOL editor for Visual Studio keeps the numbers for you: pressing Enter numbers the new line and moves every line below it up by 10, and Edit > Renumber COBOL Lines fixes a whole file. Outside the editor, tools\renumber.ps1 FILE.cbl does the same.

Comments

A * in column 7 makes the whole line a comment. A / in column 7 is also a comment, and asks for a new page when the compiler prints a listing. The pair *> starts a floating comment: it can begin in any column from 7 on, including after code on the same line, and runs to the end of the line.

Continuing a long literal

A statement can be split between words anywhere, but a quoted literal that is too long for one line needs a continuation line. Let the literal run up to column 72 without a closing quote. On the next line put - in column 7, then in area B a quote followed by the rest of the literal. Every character up to column 72 of the first line is part of the literal, spaces included, so count carefully. (An easier way to build a long value is to join shorter literals with &; see literals.)

Debugging lines

A D in column 7 marks a debugging line. It is treated as a comment unless the SOURCE-COMPUTER paragraph says WITH DEBUGGING MODE; then it is compiled like any other line. This lets you leave trace DISPLAYs in a program and switch them all on or off in one place.

SP COBOL notes

Fixed format is the default, and this reference uses it throughout. GnuCOBOL's free format (no column rules; comments start with *>) is also available: set the project property <CobolSourceFormat>free</CobolSourceFormat> in your .csproj (see BUILD.md). When the compiler complains about a wrong character in column 7 or text past column 72, the Visual Studio build adds a plain-English hint about the column rules to the error.
