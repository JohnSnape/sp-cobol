title: Special registers summary: Data items COBOL defines for you, such as RETURN-CODE, TALLY, LINAGE-COUNTER and LENGTH OF. keywords: RETURN-CODE SORT-RETURN TALLY LINAGE-COUNTER PAGE-COUNTER LINE-COUNTER XML-CODE JSON-CODE JSON-STATUS NUMBER-OF-CALL-PARAMETERS WHEN-COMPILED LENGTH OF ADDRESS OF DEBUG-ITEM COB-CRT-STATUS exit code ---

Syntax

register-name
LENGTH OF identifier-1
ADDRESS OF identifier-2
{ PAGE-COUNTER | LINE-COUNTER } [ { OF | IN } report-name ]
LINAGE-COUNTER [ { OF | IN } file-name ]

What it does

A special register is a data item that exists in every program without you declaring it. The compiler or the runtime fills it in, and you read it (and sometimes set it) like any other item. Don't define an item with one of these names.

RegisterWhat it holdsDefined as
RETURN-CODEA number a program hands back. A called program sets it before GOBACK and the caller reads it after the CALL; when the main program ends, it becomes the program's exit code (what Windows sees as %ERRORLEVEL%).binary, 9 digits, signed, starts at 0
SORT-RETURN0 after a successful SORT or MERGE, 16 after a failed one.binary, signed
TALLYA general counter, handy as the TALLYING item of INSPECT.PIC 9(5) binary, starts at 0
LINAGE-COUNTERFor a file with a LINAGE clause: the line of the page the next WRITE goes to.numeric, one per such file
PAGE-COUNTER, LINE-COUNTERFor a Report Writer report: the page number, and the last line printed on the page.numeric, one per report
NUMBER-OF-CALL-PARAMETERSIn a called program: how many arguments the caller passed.binary, signed
XML-CODE0 after a successful XML GENERATE, or an error number.PIC S9(9) binary
JSON-CODE0 after a successful JSON GENERATE, or an error number (1: the receiving item was too small).PIC S9(9) binary
COB-CRT-STATUSThe key that ended the last screen ACCEPT, when the program has no CRT STATUS clause.PIC 9(4)
WHEN-COMPILEDThe date and time the program was compiled, as text.PIC X(16)
LENGTH OF itemThe number of bytes in the item, as a constant.binary
ADDRESS OF itemWhere the item is in memory, as a pointer (see below).USAGE POINTER

RETURN-CODE and the exit code

Because RETURN-CODE becomes the exit code, a program that used it for something else should MOVE 0 TO RETURN-CODE before STOP RUN, or a batch file or build tool will think the program failed. STOP RUN RETURNING n sets the exit code on the way out; see STOP.

ADDRESS OF

ADDRESS OF is for passing data by its location: SET ptr TO ADDRESS OF item stores where an item is in a USAGE POINTER field, and SET ADDRESS OF linkage-item TO ptr makes a LINKAGE SECTION item refer to that place. Beginners rarely need it; CALL ... BY REFERENCE does the same job more safely.

WHEN-COMPILED

Its value changes every time you compile, so it isn't shown in an example here. DISPLAY WHEN-COMPILED prints something like 25/11/2604.59.02 (day/month/year, then the time, with no space between).

Examples

RETURN-CODE, TALLY, LENGTH OF, NUMBER-OF-CALL-PARAMETERS

The called program SPREGS1 (in its own source file):

       PROCEDURE DIVISION USING LS-A LS-B.
           DISPLAY "  called with " NUMBER-OF-CALL-PARAMETERS
               " argument(s)"
           IF NUMBER-OF-CALL-PARAMETERS = 2
               COMPUTE RETURN-CODE = LS-A + LS-B
           ELSE
               MOVE LS-A TO RETURN-CODE
           END-IF
           GOBACK.

TALLY counts the three A's in "BANANA SPLIT". SPREGS1 is called first with one argument, then with two; NUMBER-OF-CALL-PARAMETERS tells it which, and it hands back 7 and then 12 in RETURN-CODE. The main program sets RETURN-CODE to 0 at the end so it exits with code 0.

LINAGE-COUNTER and JSON-CODE

After each WRITE, LINAGE-COUNTER is the line the next WRITE will use. After the JSON GENERATE, JSON-CODE is 0: the text fitted in WS-JSON. With WS-JSON only 40 characters long, JSON-CODE would be 1.

COB-CRT-STATUS

A screen example (see SCREEN SECTION): the keys were "y" and Esc. There is no CRT STATUS clause, so the Esc key's code, 2005, is in COB-CRT-STATUS.

SP COBOL notes

All of these behave as in GnuCOBOL 3.2. DEBUG-ITEM is filled in while a USE FOR DEBUGGING declarative runs, which happens only when the program runs with the environment variable COB_SET_DEBUG=Y, as in GnuCOBOL (see Debugging, which has an example). The registers used by XML PARSE (XML-EVENT, XML-TEXT, ...) are defined, but XML PARSE itself is not supported (see XML PARSE). Special registers are not shown in the Visual Studio Watch window.
