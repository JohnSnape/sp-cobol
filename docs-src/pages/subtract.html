title: SUBTRACT summary: Subtract one or more numbers from a field and store the difference. keywords: FROM GIVING ROUNDED SIZE ERROR END-SUBTRACT CORRESPONDING CORR minus subtraction difference ---

Syntax

Format 1: subtract from each receiving field
SUBTRACT { identifier-1 | literal-1 } ... FROM { identifier-2 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-SUBTRACT ]

Format 2: store the difference somewhere else
SUBTRACT { identifier-1 | literal-1 } ... FROM { identifier-2 | literal-2 }
    GIVING { identifier-3 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-SUBTRACT ]

Format 3: subtract matching fields of two groups
SUBTRACT { CORRESPONDING | CORR } group-1 FROM group-2 [ ROUNDED ]
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-SUBTRACT ]

What it does

Format 1 adds up every value before FROM and subtracts that total from each field after FROM. SUBTRACT A B FROM C means "C = C - (A + B)".

Format 2 does the same subtraction but puts the answer in the GIVING field, leaving the field after FROM unchanged. SUBTRACT A FROM B GIVING C means "C = B - A". A GIVING field may be numeric-edited, such as PIC -(4)9.99.

Format 3 subtracts each numeric item of the first group from the item with the same name in the second group. Items with no partner are skipped.

Negative answers

Subtraction often gives a negative answer, so the receiving field usually needs an S in its picture (or a - if it is edited). If the field is unsigned, the sign is simply dropped: 5 - 8 stored in PIC 9(3) becomes 3, not -3, and this is not a size error.

Rounding and SIZE ERROR

Extra decimal places are cut off unless you write ROUNDED after the receiving field. If the answer has too many digits in front of the decimal point to fit, that is a size error. With ON SIZE ERROR the field keeps its old value and your statements run; without it, the high-order digits are lost. NOT ON SIZE ERROR runs when the answer fit. These work exactly as in ADD.

Example

The fee comes off BALANCE, leaving 97.50. The GIVING form subtracts the fee and the refund (12.50 together) from BALANCE without changing it, so LEFT-OVER is 85.00. 85.00 - 0.50 is 84.50, which ROUNDED makes 85 in a whole-number field. 97.50 - 200 is shown with a minus sign in an edited field. STOCK has no sign, so 5 - 8 leaves 3. SMALL is signed but only two digits long: -95 - 10 = -105 doesn't fit, so SMALL keeps -95. SUBTRACT CORRESPONDING takes SALES from SALES and RETURNS from RETURNS: 900 - 150 and 40 - 15.
