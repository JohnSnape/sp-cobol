title: SYNCHRONIZED summary: Line binary items up on memory boundaries, adding unused bytes in front of them. keywords: SYNCHRONIZED SYNC LEFT RIGHT alignment slack bytes boundary binary COMP ---

Syntax

{ SYNCHRONIZED | SYNC } [ LEFT | RIGHT ]

What it does

Processors read a 4-byte or 8-byte binary number fastest when it starts at an address that is a multiple of its size. SYNCHRONIZED asks the compiler to place a binary item (COMP, BINARY, COMP-5, POINTER, ...) on such a boundary. To do that inside a record, it inserts unused bytes, called slack bytes, in front of the item, so the record gets longer.

In SP COBOL, as in GnuCOBOL 3.2, this really changes the layout: the example's record grows from 14 to 24 bytes. On a DISPLAY item SYNC has no effect. Values and arithmetic are the same either way.

When to use it

Rarely. On a modern PC the speed difference is too small to notice, and the slack bytes change the record's length and the position of every item after them. Use SYNC only when a record layout must match one that was defined with it, such as a file written by another program or a structure passed to a C library.

LEFT and RIGHT

The words LEFT and RIGHT are accepted and give the same alignment as plain SYNC. The compiler warns that RIGHT "is not implemented", but the layout is the same as with LEFT.

Example

Without SYNC the four items are packed: 1 + 4 + 1 + 8 = 14 bytes. With SYNC, 3 slack bytes put S-COUNT at offset 4, S-CODE follows at offset 8, and 7 slack bytes put S-TOTAL at offset 16, for 24 bytes in all. The arithmetic works as usual.
