Syntax

[ USAGE [ IS ] ] { DISPLAY
                 | BINARY | COMP | COMPUTATIONAL | COMP-4
                 | COMP-5
                 | COMP-3 | PACKED-DECIMAL
                 | COMP-1 | FLOAT-SHORT
                 | COMP-2 | FLOAT-LONG
                 | INDEX
                 | POINTER
                 | NATIONAL }

What it does

The PICTURE says what values an item can hold; USAGE says how those values are kept in memory. The word USAGE IS is optional, so PIC 9(4) COMP is the usual way to write it. If you write USAGE on a group, every item in the group gets it. Without a USAGE clause, an item is DISPLAY.

Usage doesn't change what your program computes: ADD 1 gives the same answer in every form. It changes the size of the item, how fast arithmetic is, and what the bytes look like when you write a record to a file or pass it to another program.

Which one to use

Use DISPLAY (the default) while you learn: you can see the digits in a data file. Use COMP or COMP-5 for counters and subscripts. COMP-3 is common in files that came from IBM mainframes. Floating point (COMP-1, COMP-2) is for science and engineering values; it can't hold most decimal fractions exactly, so don't use it for money.

How DISPLAY shows them

A DISPLAY of a DISPLAY, COMP or COMP-3 item shows its digits as the PICTURE describes them. A COMP-5 item is shown differently: as its raw value with no decimal point, padded with zeros to the most digits its bytes can hold (5 digits for 2 bytes, 10 for 4, 20 for 8). COMP-1 and COMP-2 are shown with up to 8 and 16 significant digits, with an exponent such as E+20 for very large or small values. SP COBOL matches GnuCOBOL 3.2 in all of these.

Example: sizes and display

The same value, -1234.56, takes 9 bytes as DISPLAY, 4 as COMP or COMP-5, and 5 as COMP-3. The COMP-5 item displays as -0000123456: the stored integer, without the implied decimal point, padded to 10 digits. COMP-1 shows -1234.5601 because a 4-byte float can't hold 1234.56 exactly. A PIC 9(4) COMP-5 displays 5 digits (01234), while PIC 9(4) BINARY displays 4. After adding 1, all the forms agree.

Example: the bytes

FUNCTION HEX-OF shows the bytes of an item in hexadecimal. 258 is 1 * 256 + 2. As COMP it is stored 01 02, high byte first; as COMP-5 it is 02 01, the PC's own order. A negative COMP value is stored as its two's complement (FFFE for -2). The packed items hold the digits 1 2 3 4 5 two to a byte, ending with D for minus or F for an unsigned value. The last line shows a signed DISPLAY item: the bytes are the characters 1, 2 and s, because the minus sign is folded into the last digit.

SP COBOL notes

COMP is big-endian, as in GnuCOBOL's default configuration, so binary data files are the same bytes in both. The COMP-5 display width and the COMP-1/COMP-2 display format follow GnuCOBOL 3.2 exactly; DECISIONS.md has the details.
