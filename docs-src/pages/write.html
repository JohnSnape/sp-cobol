Syntax

Format 1: sequential and line sequential files
WRITE record-name [ FROM { identifier-1 | literal-1 } ]
    [ { BEFORE | AFTER } ADVANCING { { integer-1 | identifier-2 } [ LINE | LINES ] | PAGE } ]
    [ AT { END-OF-PAGE | EOP } imperative-statement-1 ]
    [ NOT AT { END-OF-PAGE | EOP } imperative-statement-2 ]
[ END-WRITE ]

Format 2: relative and indexed files
WRITE record-name [ FROM { identifier-1 | literal-1 } ]
    [ INVALID KEY imperative-statement-3 ]
    [ NOT INVALID KEY imperative-statement-4 ]
[ END-WRITE ]

What it does

WRITE adds the record in the record area to the file. Notice that you write a record name (the 01 under the FD), while READ takes a file name.

WRITE record FROM item first moves item into the record, then writes it. It saves a separate MOVE, and lets you build lines in WORKING-STORAGE.

The file must be open OUTPUT or EXTEND (sequential access), or OUTPUT or I-O (RELATIVE and INDEXED files with random or dynamic access). Otherwise the status is 48.

Where the record goes

  • SEQUENTIAL and LINE SEQUENTIAL: after the last record written.
  • RELATIVE: with sequential access, in the next slot (1, 2, 3, ...), and the slot number is put in the RELATIVE KEY item. If the next slot number has more digits than the RELATIVE KEY can hold, the status is 24 and nothing is written. With random or dynamic access, in the slot whose number you put in the RELATIVE KEY first. If that slot is in use, the status is 22 and INVALID KEY runs.
  • INDEXED: by the value of its RECORD KEY. A key that already exists gives 22 and INVALID KEY. With sequential access, keys must come in ascending order (21 otherwise).

Line spacing: ADVANCING

ADVANCING is for report files (LINE SEQUENTIAL). AFTER ADVANCING 2 LINES moves the paper up two lines and then prints the record, leaving one blank line before it. BEFORE ADVANCING 1 LINE prints first, then moves up. PAGE starts a new page: a form feed character in the file, or blank lines to the end of the page when the file has LINAGE.

A plain WRITE (no ADVANCING) prints the record and then ends the line. A WRITE ... AFTER ADVANCING moves first and does not end its own line. So a plain WRITE straight after an AFTER ADVANCING one lands on the same line, right after the previous record. In a report, use AFTER ADVANCING on every WRITE (or BEFORE on every WRITE); don't mix them with plain WRITEs.

Pages: LINAGE and END-OF-PAGE

An FD with LINAGE IS 4 LINES WITH FOOTING AT 3 LINES AT TOP 1 LINES AT BOTTOM 1 describes a page with a 1-line top margin, a body of 4 lines, and a 1-line bottom margin. The footing area is lines 3 and 4 of the body. The special register LINAGE-COUNTER holds the line of the body the next WRITE will use. When a WRITE reaches the footing area, or the page is full and the runtime moves to the next page, the AT END-OF-PAGE statements run; that is where a program prints page totals or a new heading.

Examples

WRITE FROM and ADVANCING

Every WRITE uses AFTER ADVANCING, so each record moves down first: the file starts with an empty line, and the 2-line advances leave a blank line before TEA and before END. The program reads the file back to show the lines.

LINAGE and AT END-OF-PAGE

After line 2, LINAGE-COUNTER is 3, the start of the footing, so AT END-OF-PAGE runs; again after line 3. Line 4 fills the page, the runtime moves to the next page and LINAGE-COUNTER starts again at 1. On the second page line 6 reaches the footing. AFTER ADVANCING PAGE pads the rest of the page with blank lines and prints at the top of a new one.

INVALID KEY on a relative file

Locker 12 is free the first time, so the NOT INVALID KEY branch runs. The second WRITE to slot 12 finds it in use: status 22, INVALID KEY.

A RELATIVE KEY that is too small

BIN-NO has one digit, so it can number slots 1 to 9. The first nine WRITEs fill those slots. The tenth would go in slot 10, which BIN-NO can't hold: status 24, and the record is not written, so the file has nine records. Give the RELATIVE KEY enough digits for every slot the file will have. GnuCOBOL 3.2 prints something else here (see the notes below).

SP COBOL notes

As in GnuCOBOL 3.2, LINAGE files get blank lines rather than form feeds between pages, and lines end with CR LF.

Differs from GnuCOBOL 3.2, on purpose. When a sequential WRITE reaches a slot number that doesn't fit the RELATIVE KEY, SP COBOL returns 24, the COBOL standard's code for it, and writes nothing. GnuCOBOL 3.2 returns 00, writes the record in the next slot anyway and sets the key to 0. See Differences from GnuCOBOL.
