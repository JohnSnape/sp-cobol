title: XML GENERATE summary: Turn a group item and its fields into XML text. keywords: XML GENERATE FROM COUNT IN XML-DECLARATION ATTRIBUTES NAME OF TYPE OF ATTRIBUTE ELEMENT CONTENT SUPPRESS WHEN NAMESPACE NAMESPACE-PREFIX ON EXCEPTION XML-CODE END-XML markup ---

Syntax

XML GENERATE identifier-1 FROM identifier-2
    [ COUNT IN identifier-3 ]
    [ WITH XML-DECLARATION ]
    [ WITH ATTRIBUTES ]
    [ NAMESPACE IS { identifier-4 | literal-1 }
        [ NAMESPACE-PREFIX IS { identifier-5 | literal-2 } ] ]
    [ NAME OF { identifier-6 IS literal-3 } ... ]
    [ TYPE OF { identifier-7 IS { ATTRIBUTE | ELEMENT | CONTENT } } ... ]
    [ SUPPRESS { identifier-8 ...
               | WHEN { SPACES | ZEROS | LOW-VALUES | HIGH-VALUES } } ]
    [ ON EXCEPTION imperative-statement-1 ]
    [ NOT ON EXCEPTION imperative-statement-2 ]
[ END-XML ]

What it does

XML is a text format that marks data with named tags, like <PRICE>4.50</PRICE>. XML GENERATE takes the data item after FROM, usually a group, and writes it as XML into the alphanumeric field identifier-1.

How the data becomes XML

  • Each item becomes an element: a start tag with the item's COBOL name, the value, and an end tag. A group's element contains the elements of its items.
  • Numeric values are written as numbers: leading zeros are dropped, and the sign and the decimal point are shown (0017 becomes 17).
  • Text values lose their trailing spaces; a field of all spaces becomes one space.
  • The characters that have a meaning in XML are escaped: & becomes &amp;, < becomes &lt;, > becomes &gt; and a double quote becomes &quot;.
  • FILLER items are left out.

The XML text goes at the start of the output field. COUNT IN gives its length, so XML-OUT (1:LEN) is exactly the XML.

The optional phrases

  • WITH XML-DECLARATION starts the text with <?xml version="1.0"?> and a line break.
  • WITH ATTRIBUTES writes elementary items as attributes of their group's start tag (<ITEM ITEM-NO="0017">) instead of as separate elements. Groups stay elements.
  • TYPE OF item IS ATTRIBUTE or IS ELEMENT chooses for one item, overriding WITH ATTRIBUTES. IS CONTENT writes the value as the bare text of the group's element, without a tag of its own.
  • NAME OF item IS "name" uses your own tag name instead of the COBOL name.
  • SUPPRESS item ... leaves the named items out. SUPPRESS WHEN SPACES (or ZEROS, LOW-VALUES, HIGH-VALUES) leaves out every element whose value is all spaces (or zero, and so on).
  • NAMESPACE IS adds an XML namespace (a URI that identifies the vocabulary) to the outer element. With NAMESPACE-PREFIX IS "m" every tag gets the prefix m:.

XML-CODE and ON EXCEPTION

The special register XML-CODE is zero after a successful XML GENERATE. If the output field is too small, XML-CODE is 400, the field holds what fit, and the ON EXCEPTION statements run. Other nonzero codes report bad data: for example, a text field containing control characters is written as hexadecimal in an element called hex.NAME and XML-CODE is 417, and a namespace that isn't a valid URI gives 416. NOT ON EXCEPTION runs when there was no exception.

Examples

The first XML GENERATE uses no options: every item is an element, ITEM-NO loses its leading zeros, and the ampersand in the description is escaped. The second adds the XML declaration, renames ITEM and ITEM-NO, makes ITEM-NO an attribute and drops NOTE-TEXT because it is all spaces. The third writes all the elementary items as attributes, except the SIZES group. Note that attribute values are the field's raw characters: 0017 and 00450, with no decimal point. The last one doesn't fit in 20 characters, so XML-CODE is 400.

In the first statement WITH ATTRIBUTES makes X-POS, Y-POS and QTY attributes, while TYPE OF keeps LABEL-TEXT an element. QTY is zero but still appears: SUPPRESS WHEN only removes items written as elements. The second statement writes elements with a namespace and the prefix m:, and this time the zero QTY element is suppressed.

SP COBOL notes

SP COBOL writes the XML itself, so no extra library has to be installed (GnuCOBOL uses libxml2). The text, the XML-CODE values and the COUNT IN results are the same as in GnuCOBOL 3.2, quirks included:

  • A table (OCCURS) is not repeated: only its first entry is generated, and the compiler warns that this is "not implemented".
  • Attribute values are the raw characters of the field, so a negative number shows its sign as an overpunched last character (-123.45 in PIC S9(5)V99 appears as 001234u).
  • When the output field is too small, COUNT IN is one more than the length of the complete XML text (it counts a final line break).
  • A COMP-1 or COMP-2 item in the data stops the program with a runtime error, as GnuCOBOL's runtime does. Move such values to a display field first.
