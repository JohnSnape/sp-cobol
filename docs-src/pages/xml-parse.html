Syntax

XML PARSE identifier-1
    PROCESSING PROCEDURE procedure-1 [ { THRU | THROUGH } procedure-2 ]
    [ ON EXCEPTION imperative-statement-1 ]
    [ NOT ON EXCEPTION imperative-statement-2 ]
[ END-XML ]
XML PARSE is not supported. SP COBOL stops with a compile error when a program uses it.

What it does (in other compilers)

In compilers that implement it, XML PARSE reads an XML document from a field and calls the processing procedure once for every part it finds: the start of the document, each start tag, each piece of text, each end tag, and so on. Inside the procedure, special registers such as XML-EVENT (what was found) and XML-TEXT (the text of it) tell your code what to do with each part.

Example

The compiler accepts the syntax, then rejects the statement with an error. The warning line is GnuCOBOL's own; the error line comes from SP COBOL.

SP COBOL notes

GnuCOBOL 3.2 doesn't implement XML PARSE either. It compiles the statement, but when the program runs, the runtime delivers the first event and then stops the program with the message "XML PARSE is not implemented". Rather than build a program that half runs, SP COBOL reports the problem when you compile.

What to do instead

  • If the XML always has the same simple, known layout (one record per line, the same tags in the same order), you can pick it apart yourself: UNSTRING with the tags as delimiters, or INSPECT to find and count them, with reference modification to take out the values. This only works for XML you control; it is not a general XML reader.
  • For real-world XML, let a program in another language (C#, for example, which has a full XML reader built in) convert the document into a plain fixed-layout or line sequential file, and read that file from COBOL with READ.
  • To write XML, use XML GENERATE, which is supported.
