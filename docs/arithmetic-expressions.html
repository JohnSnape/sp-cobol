    Using data

    Arithmetic expressions

    Formulas built from numbers, data items and the operators + - * / **, as used in COMPUTE.

    Syntax

    operand  [ { + | - | * | / | ** } operand ] ...

operand:
    identifier | numeric-literal | FUNCTION function-name [ ( arguments ) ]
  | ( arithmetic-expression ) | { + | - } operand

    What it does

    An arithmetic expression is a formula: numbers and numeric data items joined by operators. Its main home is COMPUTE: COMPUTE PAY = HOURS * RATE. Expressions are also allowed in reference modification (TEXT-1 (N - 2 : N + 1)) and in conditions, so you can write IF A * 2 > B + 10 or PERFORM UNTIL N * N > 30 without first COMPUTEing the value into a field.

    OperatorMeaningExample
    +addA + B
    -subtract (or, in front of one operand, negate) A - B, - A
    *multiplyA * B
    /divideA / B
    **raise to a power2 ** 10, 9 ** 0.5 (square root)
    Put a space on both sides of every operator. A-B is not "A minus B": a hyphen between letters makes it one name, A-B. Write A - B.

    Order of operations

    As in ordinary arithmetic:

    1. parentheses, innermost first;
    2. a sign in front of an operand (unary + or -);
    3. **;
    4. * and /, left to right;
    5. + and -, left to right.

    So A + B * 2 multiplies first, and A - B - 1 is (A - B) - 1. Several ** in a row are worked from the right in GnuCOBOL: 2 ** 3 ** 2 is 2 ** 9, 512. When in doubt, add parentheses.

    Precision of the working values

    While an expression is worked out, COBOL keeps far more digits than any field holds, so A / B is not cut to the size of A or B. The answer is only fitted to the receiving field at the end: extra decimal places are dropped, or rounded if you write ROUNDED. Because of that, the order of operations still matters for division. 1 / 3 * 3 works out 1 / 3 as 0.3333... with many digits but not infinitely many, so the product is a little under 1 and a field with two decimals gets 0.99; with ROUNDED it gets 1.00. Multiplying first (1 * 3 / 3) avoids the problem.

    If the answer is too big for the receiving field, or you divide by zero, that is a size error; see COMPUTE for ON SIZE ERROR.
