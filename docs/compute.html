    Statements

    COMPUTE

    Work out an arithmetic expression and store the result.

    Syntax

    COMPUTE { identifier-1 [ ROUNDED [ MODE IS rounding-mode ] ] } ...
        { = | EQUAL } arithmetic-expression
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-COMPUTE ]

    What it does

    COMPUTE works out the formula on the right of = and stores the answer in the field (or fields) on the left. The formula can use + - * /, ** for "to the power of", parentheses, numeric fields, literals and numeric functions; the rules are on the arithmetic expressions page. EQUAL is another way to write =.

    Use COMPUTE whenever a calculation has more than one step. COMPUTE TOTAL = PRICE * QTY * (1 + TAX-RATE) is one line, where ADD and MULTIPLY would need several statements and a work field.

    Several receiving fields

    You can list more than one field before the =. The formula is worked out once and the answer is stored in each field, following each field's own PICTURE and ROUNDED phrase.

    ROUNDED

    While working out the formula, COBOL keeps enough decimal places for an exact (or nearly exact) answer. When that answer is stored, extra decimal places that don't fit the field are dropped, unless you write ROUNDED after the field. ROUNDED rounds a final digit of 5 or more away from zero: 64.46 stored in one decimal place becomes 64.5, and -2.5 stored in a whole number becomes -3.

    ROUNDED MODE

    ROUNDED MODE IS picks another way of rounding for that field:

    ModeWhat it does2.5-2.52.1
    NEAREST-AWAY-FROM-ZERONearest; a half goes away from zero. This is what plain ROUNDED does.3-32
    NEAREST-EVENNearest; a half goes to the even digit ("banker's rounding").2-22
    NEAREST-TOWARD-ZERONearest; a half goes toward zero.2-22
    AWAY-FROM-ZEROAny extra digits push the number away from zero.3-33
    TRUNCATIONDrop the extra digits (the same as no ROUNDED).2-22
    TOWARD-GREATERAlways up, toward the larger number.3-23
    TOWARD-LESSERAlways down, toward the smaller number.2-32
    PROHIBITEDThe answer must fit exactly; if digits would be lost, it is a size error and the field keeps its old value.errorerrorerror

    The same phrase works on ADD, SUBTRACT, MULTIPLY and DIVIDE.

    SIZE ERROR

    A size error happens when the answer has more digits before the decimal point than the field can hold, or when the formula divides by zero. With ON SIZE ERROR, the field keeps its old value and your statements run. NOT ON SIZE ERROR runs when the answer was stored. Without the phrase, a too-big answer loses its high-order digits silently, and a division by zero leaves the field unchanged.

    Write END-COMPUTE when the COMPUTE has a SIZE ERROR phrase and sits inside another statement such as IF.

    Examples

    19.99 × 3 × 1.075 is 64.46775. TOTAL has two decimal places, so it gets 64.46 (the rest is dropped). The second COMPUTE stores the same answer in two fields: CUT drops the extra digits, NEAR is ROUNDED to 64.5. 3 ** 4 is 81, which fits in PIC 99, so NOT ON SIZE ERROR runs. 3 ** 5 is 243, which doesn't fit, so SMALL keeps 81. Dividing by ZERO-QTY is a size error too, and AVERAGE keeps its value of 5.

    Rounding modes

    Each value is stored in five one-digit fields, each rounded its own way. Plain ROUNDED and NEAREST-EVEN differ only on an exact half: 2.5 goes up to 3 with ROUNDED but down to the even 2 with NEAREST-EVEN, while 3.5 goes to 4 both ways. AWAY-FROM-ZERO rounds 2.1 up to 3 because any leftover counts. UP (TOWARD-GREATER) and DOWN (TOWARD-LESSER) ignore the size of the leftover and look only at the direction, so -2.5 goes up to -2 and down to -3.

    SP COBOL notes

    Division by zero leaves the receiving field unchanged and raises SIZE ERROR, as in GnuCOBOL.
