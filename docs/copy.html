    Compiler directives

    COPY

    Bring the text of a copybook into the program as it is compiled.

    Syntax

    COPY { text-name | literal-1 }
    [ REPLACING { { ==pseudo-text-1== | word-1 } BY { ==pseudo-text-2== | word-2 } } ... ] .

    What it does

    COPY is not a statement that runs; it is an instruction to the compiler. Before the program is compiled, the COPY is replaced by the whole text of another file, called a copybook. It works anywhere in the program: in the DATA DIVISION to share a record layout between programs, in the PROCEDURE DIVISION to share code. Change the copybook, rebuild, and every program that copies it picks up the change.

    The COPY ends with a period. That period belongs to the COPY, not to the copied text, so COPY can sit in the middle of a paragraph without ending a sentence.

    Naming the copybook

    Write the name with or without quotes: COPY CUSTREC. or COPY "CUSTREC.cpy". Without an extension, the compiler tries the name with the usual extensions, including .cpy, which is what SP COBOL projects use. A copybook is written in the same source format as the program.

    REPLACING

    REPLACING changes text on its way in. Each pair says what to find and what to put in its place. Text between == marks is pseudo-text: a run of one or more COBOL words matched word by word, so spacing doesn't matter. This lets one copybook serve for several records: write a placeholder in it, such as :TAG: inside each name, and replace the placeholder differently in each COPY. A placeholder in colons can be part of a longer word (:TAG:-NAME becomes OLD-NAME).

    Where copybooks are found

    The compiler looks for a copybook in the current folder, in each folder given to it with -I, in the folders listed in the COBCPY environment variable, and in its own copybook folder (COB_COPY_DIR, which holds GnuCOBOL's standard copybooks such as screenio.cpy).

    In an SP COBOL project in Visual Studio you don't set any of this up. Put the .cpy files in the project folder (or a subfolder) and add them to the project. The build passes the project folder, the folder of every .cbl file, and the folder of every .cpy file in the project to the compiler with -I, so COPY CUSTREC. finds CUSTREC.cpy wherever it sits in the project. A program is also rebuilt when one of the project's copybooks changes.

    Example: sharing a record and some code

    The copybook COPY1REC.cpy holds the record layout:

    000010*> COPY1REC: the customer record, shared by every program
000020 01  CUSTOMER-REC.
000030     05  CUST-NAME       PIC X(15).
000040     05  CUST-BALANCE    PIC 9(4)V99.

    and COPY1SHOW.cpy, named here in quotes with its extension, holds two statements:

    000010     DISPLAY "NAME:    " CUST-NAME
000020     DISPLAY "BALANCE: " CUST-BALANCE

    The first COPY puts the record into WORKING-STORAGE; the second puts the two DISPLAYs into the PROCEDURE DIVISION, so the program runs as if they had been typed in place.

    Example: REPLACING

    COPY2REC.cpy is a record with a placeholder in every name:

    000010 01  :TAG:-RECORD.
000020     05  :TAG:-NAME      PIC X(8).
000030     05  :TAG:-AMOUNT    PIC 9(4).

    The first COPY makes OLD-RECORD, OLD-NAME and OLD-AMOUNT. The second makes the NEW- names and also replaces 9(4) by 9(6), so NEW-AMOUNT has room for 120000.

    SP COBOL notes

    COPY is handled by GnuCOBOL's own front end, so it behaves exactly as in GnuCOBOL 3.2.
