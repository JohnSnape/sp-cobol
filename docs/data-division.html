    Divisions

    DATA DIVISION

    Describe every piece of data the program uses, section by section.

    Syntax

    DATA DIVISION.
[ FILE SECTION.
    { FD | SD } file-name [ file-clauses ] .
        record-description ... ]
[ WORKING-STORAGE SECTION.
    data-description ... ]
[ LOCAL-STORAGE SECTION.
    data-description ... ]
[ LINKAGE SECTION.
    data-description ... ]
[ REPORT SECTION.
    report-description ... ]
[ SCREEN SECTION.
    screen-description ... ]

data-description:
level-number { data-name | FILLER } [ clauses ] .

    What it does

    Every data item a program uses is described in the DATA DIVISION before the code runs: its name, its size and what kind of data it holds. COBOL has no "declare as you go"; if it isn't here, the PROCEDURE DIVISION can't use it. The sections must appear in the order above, and you include only the ones you need.

    SectionWhat it holds
    FILE SECTIONOne FD (file description) for each file named in a SELECT, followed by its record layout: the area a READ fills and a WRITE takes from. SD describes a sort work file. See files and SORT.
    WORKING-STORAGE SECTIONThe program's own data. It is set up once, when the program first runs, and keeps its values for as long as the program is loaded, including between CALLs of a subprogram.
    LOCAL-STORAGE SECTIONLike WORKING-STORAGE, but set up fresh (with its VALUE clauses) every time the program is called. See SP COBOL notes.
    LINKAGE SECTIONDescribes data that belongs to the calling program, passed in through PROCEDURE DIVISION USING. No storage is set aside here; the names are laid over the caller's items. See CALL.
    REPORT SECTIONReport layouts for the Report Writer. See Report Writer.
    SCREEN SECTIONScreen layouts for ACCEPT and DISPLAY of whole screens. See SCREEN SECTION.

    Data descriptions and level numbers

    Each entry starts with a level number, then the item's name (or FILLER for a part you never refer to by name), then clauses such as PICTURE, VALUE, USAGE and OCCURS, and ends with a period.

    • 01 starts a record: a new item at the top level, in area A.
    • 02 to 49 are parts of the item above them with a smaller number. Most programs use 05, 10, 15, ... so there is room to add levels later.
    • 77 is a stand-alone elementary item that can't have parts.
    • 88 names a condition on the item above it; 66 renames part of a record. See condition names and RENAMES.

    The full rules are on the level numbers page.

    Group and elementary items

    An item with parts under it is a group item; an item with no parts is an elementary item. Only elementary items have a PICTURE. A group is simply its parts laid end to end, and when you use the group name you get all of them as one alphanumeric field, whatever their own pictures say. MOVE to a group fills the whole group as text.

    Example

    CUSTOMER is a group of two parts: CUST-NAME (itself a group of FIRST-NAME and LAST-NAME) and CUST-BALANCE. Displaying CUSTOMER shows all 20 bytes in a row, with the balance as its six digits and no decimal point, since the group is just text. MOVE SPACES to CUST-NAME clears both names but leaves the balance alone. VISITS is a level 77 item.

    SP COBOL notes

    LOCAL-STORAGE SECTION is accepted by the compiler, but in this preview a program that has one doesn't build (the generated C# fails to compile). Use WORKING-STORAGE and set the items at the start of the program yourself, or mark the subprogram IS INITIAL (see IDENTIFICATION DIVISION) so its WORKING-STORAGE starts fresh on every CALL.
