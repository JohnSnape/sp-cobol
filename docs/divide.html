    Statements

    DIVIDE

    Divide one number by another, optionally keeping the remainder.

    Syntax

    Format 1: divide into a field, replacing it
DIVIDE { identifier-1 | literal-1 } INTO { identifier-2 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-DIVIDE ]

Format 2: store the quotient somewhere else
DIVIDE { identifier-1 | literal-1 } { INTO | BY } { identifier-2 | literal-2 }
    GIVING { identifier-3 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-DIVIDE ]

Format 3: quotient and remainder
DIVIDE { identifier-1 | literal-1 } { INTO | BY } { identifier-2 | literal-2 }
    GIVING identifier-3 [ ROUNDED ] REMAINDER identifier-4
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-DIVIDE ]

    What it does

    The word between the two values says which one is divided:

    • DIVIDE A INTO B means B / A ("A goes into B").
    • DIVIDE A BY B means A / B. BY needs GIVING.

    Format 1 divides each field after INTO by the first value and stores the answer back in that field. Format 2 leaves both values alone and stores the answer, the quotient, in the field after GIVING, which may be a numeric-edited field. Format 3 also stores the remainder: what is left over, dividend minus quotient times divisor. DIVIDE 60 INTO 125 GIVING HOURS REMAINDER MINS gives 2 hours and 5 minutes.

    Decimals and ROUNDED

    The quotient is cut to the decimal places of its field, unless you write ROUNDED, which rounds a last digit of 5 or more away from zero. For the REMAINDER, COBOL uses the quotient cut to its field's decimal places, before any rounding.

    With a negative dividend the remainder is negative too: -17 / 5 gives a quotient of -3 and a remainder of -2.

    SIZE ERROR and dividing by zero

    A size error happens when the quotient (or remainder) has more digits before the decimal point than its field holds, and whenever the divisor is zero. With ON SIZE ERROR the receiving fields keep their old values and your statements run instead. Dividing by zero never stores anything, with or without the phrase, so test for it.

    Examples

    100 / 4 is 25. DIVIDE 2 INTO QUARTER (Format 1) halves QUARTER in place: 12.5, cut to 12 because QUARTER has no decimal places. 100 / 7 is 14 with 2 left over (14 × 7 = 98). The ROUNDED quotient 14.2857... becomes 14.29. 125 minutes is 2 hours and 5 minutes. 100 / 8 is 12.5, too many digits for PIC 9, so TINY keeps 5. DIVIDE 0 INTO SHARE is a division by zero, a size error, so SHARE keeps the 14 it had.

    The remainder with a ROUNDED quotient

    20 / 3 is 6.67. The first DIVIDE stores 6 and a remainder of 20 - 6 × 3 = 2. The second rounds the quotient to 7, but the remainder is still 2: it is worked out from the quotient before rounding (6), cut to the quotient field's decimal places, not from the rounded 7. The last line shows the signs with a negative dividend.

    SP COBOL notes

    As in GnuCOBOL, the remainder uses the quotient truncated to the quotient field's decimal places, even when the quotient is ROUNDED.
