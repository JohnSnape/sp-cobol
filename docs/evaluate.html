    Statements

    EVALUATE

    Choose one of several actions by comparing values or testing conditions; COBOL's case statement.

    Syntax

    EVALUATE subject-1 [ ALSO subject-2 ] ...
    { { WHEN object-1 [ ALSO object-2 ] ... } ...
          imperative-statement-1 } ...
    [ WHEN OTHER imperative-statement-2 ]
[ END-EVALUATE ]

subject:  { identifier | literal | arithmetic-expression | condition | TRUE | FALSE }

object:   { ANY
          | condition
          | TRUE | FALSE
          | [ NOT ] { identifier-1 | literal-1 | arithmetic-expression-1 }
                [ { THRU | THROUGH } { identifier-2 | literal-2 | arithmetic-expression-2 } ] }

    What it does

    EVALUATE looks at a value (the subject) and runs the statements under the first WHEN that matches it. Only one WHEN runs; then the program goes on after END-EVALUATE. If no WHEN matches, the statements under WHEN OTHER run, or nothing at all if there is no WHEN OTHER. It does the job of a long chain of IF ... ELSE IF ..., and is much easier to read.

    What a WHEN can say

    • A value: WHEN "A", WHEN 100, WHEN LIMIT-AMT. Matches when the subject equals it.
    • A range: WHEN 90 THRU 100 matches anything from 90 to 100, both ends included.
    • NOT before a value or range: matches when the subject is anything else.
    • ANY: matches every value. It is most useful with ALSO, to say "this subject doesn't matter here" (WHEN 0 THRU 12 ALSO ANY).
    • With EVALUATE TRUE, each WHEN is a condition (WHEN AGE < 18, WHEN IS-MEMBER), and the first one that is true is chosen. With EVALUATE FALSE, the first condition that is false is chosen.

    Several WHENs sharing one action

    Write the WHENs one after another with no statement between them. The statements after the last one run when any of them matches.

    ALSO: more than one subject

    EVALUATE AGE ALSO MEMBER-FLAG tests two things at once. Each WHEN then has one object per subject, separated by ALSO, and matches only when every pair matches. This is a decision table written as code. Subjects may be of different kinds: EVALUATE TRUE ALSO QTY takes a condition and then a value in each WHEN.

    Two subjects, and EVALUATE TRUE

    The first EVALUATE is a small decision table on age and membership. A 70-year-old non-member matches 65 THRU 999 ALSO "N". A 40-year-old non-member matches nothing and gets the OTHER branch. The second EVALUATE tests conditions in order: the 10-year-old is caught by the first WHEN, so the member test is never reached for that row.

    EVALUATE FALSE, and NOT in a WHEN

    In the first EVALUATE each WHEN fires when its condition is false. Both conditions are true here, so WHEN OTHER runs. In the second, QTY 5 is in the range 1 THRU 9, so the first WHEN matches; a QTY of 0 or 10 or more would have matched NOT 1 THRU 9.

    WHEN ANY

    The ticket table again, shorter. A child pays the child price whether or not they are a member, so the first WHEN says ALSO ANY instead of listing "Y" and "N". Any member older than 12 then matches ANY ALSO "Y", because the children were already caught by the first WHEN. The 70-year-old non-member gets the senior ticket.
