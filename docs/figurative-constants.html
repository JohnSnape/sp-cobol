    Using data

    Figurative constants

    Reserved words such as ZERO, SPACES and HIGH-VALUES that stand for a value and fill a whole field.

    Syntax

    { ZERO | ZEROS | ZEROES }
{ SPACE | SPACES }
{ HIGH-VALUE | HIGH-VALUES }
{ LOW-VALUE | LOW-VALUES }
{ QUOTE | QUOTES }
ALL literal
{ NULL | NULLS }

    What it does

    A figurative constant is a word that stands for a value. Unlike a literal it has no fixed length: it repeats as often as needed to fill whatever it is moved to or compared with. The singular and plural spellings mean exactly the same thing.

    WordValueTypical use
    ZERO, ZEROS, ZEROESThe number 0, or the character "0" repeated in a text field.Clearing totals and counters.
    SPACE, SPACESBlank characters.Clearing text fields and records; testing for an empty field.
    HIGH-VALUE, HIGH-VALUESThe highest byte value, X"FF" (255).A key that sorts after every real key, such as an end-of-file marker when matching two files.
    LOW-VALUE, LOW-VALUESThe lowest byte value, X"00".A key that sorts before everything; filling a field with binary zeros.
    QUOTE, QUOTESThe quotation mark character ".Building text that contains quotes.
    ALL literalThe literal repeated: ALL "AB" fills a field with ABABAB...Lines of dashes or stars; filling with a pattern.
    NULL, NULLSThe null address.Only with USAGE POINTER items: SET PTR TO NULL, IF PTR = NULL (see SET).

    Where you can use them

    • As the source of a MOVE: MOVE SPACES TO CUST-NAME fills every byte of CUST-NAME. Moved to a numeric field, ZERO sets it to 0.
    • In a VALUE clause: 01 TOTAL PIC 9(5) VALUE ZERO.
    • In a comparison: IF CUST-NAME = SPACES is true when the field is all blanks, however long it is. The same goes for HIGH-VALUES, LOW-VALUES and ALL "x": IF END-KEY = HIGH-VALUES is true only when every byte is a high value.

    Only ZERO makes sense for a numeric field. SPACE, QUOTE and ALL "x" are for alphanumeric fields; HIGH-VALUES and LOW-VALUES are bytes, not numbers.

    Examples

    TEXT-6 starts as SPACES and NUM-4 as ZERO, from their VALUE clauses. Moving ZEROS to a text field fills it with the character 0. ALL "AB" repeats the pattern across all six bytes. HIGH-VALUES and LOW-VALUES are bytes you can't see on the screen, so the program shows the code of the first byte instead: 255 and 0. The last test compares part of the field with SPACES; the figurative constant takes the length of whatever it is compared with.

    Comparing with figurative constants

    Each constant is stretched to the six bytes of the field it is compared with. END-KEY and START-KEY were filled from their VALUE clauses, so they match. Any ordinary text such as SMITH lies between LOW-VALUES and HIGH-VALUES, which is why they make good "before everything" and "after everything" keys. ALL "AB" is compared as ABABAB. Changing one byte of STARS is enough to make it unequal to ALL "*".
