    FILE STATUS codes

    The two-character code set after every file operation, what each value means, and how to test it.

    Syntax

    SELECT file-name ASSIGN TO ...
    FILE STATUS IS identifier-1 .

WORKING-STORAGE SECTION.
01 identifier-1 PIC XX.
   [ 88 condition-name VALUE "nn" [ "nn" ] ... . ] ...

    What it does

    After every OPEN, CLOSE, READ, WRITE, REWRITE, DELETE and START on a file, the runtime stores a two-character code in the file's FILE STATUS item. "00" means the statement worked. Anything else tells you what happened, so you can react instead of letting the program stop.

    The first character is the class of the result:

    • 0: success. The second digit may add a remark (a duplicate alternate key, a missing OPTIONAL file, a shortened record).
    • 1: AT END. There is no next record.
    • 2: INVALID KEY. A key was wrong for this operation: not found, already there, or out of order.
    • 3: a permanent error, usually with the file itself: missing, not allowed, or not the shape the program expects.
    • 4: a logic error: the statement didn't make sense at that moment, such as reading a file that isn't open.
    • 9: other errors from the runtime.

    When a statement fails (class 3, 4 or 9, or 1 and 2 with no AT END / INVALID KEY phrase) and the file has neither a FILE STATUS item nor a USE procedure, the program stops with an error message. With a FILE STATUS item, the program carries on and it's up to you to look at the code.

    Declaring and testing it

    Declare the item as PIC XX in WORKING-STORAGE, and name it in the SELECT. Testing it with 88-level condition names makes the code read well: IF FS-NOT-FOUND rather than IF FS = "35". Check it right after the statement; the next file statement replaces it. To act on a whole class, test the first character: IF FS(1:1) = "3".

    The codes

    CodeMeaningWhat to check
    00Success.
    02Success, and another record has the same alternate key value (INDEXED, WITH DUPLICATES). On READ it means the next record has the same key. Nothing, unless the key was meant to be unique.
    04Success, but the record read was not the length the FD allows (too short or too long for a variable-length record).The RECORD VARYING sizes against the file.
    05OPEN of an OPTIONAL file that doesn't exist. The open worked; reading gives end of file at once.Nothing; this is how OPTIONAL files work.
    06READ of a LINE SEQUENTIAL line longer than the record: you got the first part, the next READ returns the rest.Make the record longer.
    07CLOSE REEL / UNIT or NO REWIND on a disk file: done, but the phrase has no meaning on disk.Use a plain CLOSE.
    09READ of a LINE SEQUENTIAL line containing a control character such as Ctrl-Z.The file may not be text.
    10End of file: no next record (sequential READ, READ NEXT, RETURN). Normal at the end of a loop.
    14Sequential READ of a RELATIVE file reached a slot number too big for the RELATIVE KEY item. The record is still read, and the key is set to 0.Give the RELATIVE KEY more digits.
    21Key out of order: an INDEXED file with sequential access must be written in ascending key order (after OPEN EXTEND too: above the highest key already there).Sort the data first, or use random access.
    22Duplicate key: WRITE to a RELATIVE slot that is in use, or WRITE of an INDEXED record whose RECORD KEY is already in the file.Read first, or REWRITE instead.
    23Record not found: READ, START, REWRITE or DELETE of a key or slot that isn't there.The key value; normal when looking things up.
    24Key outside the file's limits, such as RELATIVE KEY 0, or a sequential WRITE of a RELATIVE file whose next slot number is too big for the RELATIVE KEY item (nothing is written).Slot numbers start at 1. Give the RELATIVE KEY more digits.
    30Permanent error reported by Windows while reading or writing. The disk, the path, the file.
    31The file name is empty or badly quoted.The ASSIGN data item has a name in it when OPEN runs.
    35OPEN INPUT, I-O or EXTEND of a file that doesn't exist.The name, and the current folder. Use OPEN OUTPUT or SELECT OPTIONAL to create it.
    37Permission denied: the file is read-only, or the name is a folder. The file's properties.
    38OPEN of a file closed earlier WITH LOCK.Don't lock it if you need it again.
    39The file doesn't match the program: wrong record size, or (INDEXED) a different key layout.The FD against the program that wrote the file.
    41OPEN of a file that is already open.CLOSE it first.
    42CLOSE of a file that isn't open.
    43REWRITE or DELETE with sequential access, with no successful READ just before.READ the record first.
    44Record size wrong: WRITE or REWRITE of a record shorter or longer than the FD allows.The DEPENDING ON item before WRITE.
    46READ after the previous READ already hit end of file or failed. Stop the loop at status 10.
    47READ or START on a file that isn't open for INPUT or I-O (or is closed).The OPEN mode.
    48WRITE on a file that isn't open for OUTPUT, EXTEND (or I-O for RELATIVE and INDEXED).The OPEN mode.
    49REWRITE or DELETE on a file not open I-O.Open it I-O.
    57The LINAGE values make no sense (footing beyond the page, for example).The LINAGE clause.
    61The file is already open elsewhere, in this program or another one. Close the other user, such as Excel.
    91The operation isn't available for this kind of file.

    GnuCOBOL also defines 34 (disk full or a boundary passed) and 51 (record locked); SP COBOL doesn't produce them.

    Examples

    Each line shows the status after one statement on a sequential file: 35 because the file doesn't exist yet, 41 for opening twice, 47 for reading a file opened for output, 42 for closing twice, 48 for writing a closed file, 10 at the end, 46 for reading past the end, 49 for REWRITE when the file is open INPUT, and 43 for REWRITE with no READ before it.

    The key and record codes: 22 for a slot already in use, 24 for slot 0, 23 for an empty slot, 44 for a 1-character record when the FD says at least 2. Reading a 10-character line into a 6-character record gives 06 and the first six characters; the next READ returns the rest with 00. CLOSE ... REEL on a disk file gives 07 and leaves the file open, so a plain CLOSE follows.

    Slots 8 to 11 are written through ROOM-NO, which has two digits. The file is then read in order through a second SELECT whose RELATIVE KEY, SHORT-NO, has only one digit. Slots 8 and 9 read normally. Slot 10 doesn't fit: status 14, SHORT-NO is set to 0, and the record ROOM10 is still read.

    SP COBOL notes

    The codes are the ones GnuCOBOL 3.2 sets in each situation. The exceptions are listed on the Files page, for example REWRITE or DELETE of an empty RELATIVE slot, which gives 23 here and 00 in GnuCOBOL, and a sequential WRITE whose slot number doesn't fit the RELATIVE KEY, which gives 24 here and 00 in GnuCOBOL (see WRITE).

    When a file error stops the program, SP COBOL adds a hint: line under GnuCOBOL's message saying what to check. COB_NO_HINTS=1 turns it off.
