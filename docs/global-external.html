    Data description

    GLOBAL and EXTERNAL

    Share data with nested programs (GLOBAL) or between separately compiled programs (EXTERNAL).

    Syntax

    01 data-name [ other clauses ] [ IS ] GLOBAL .
01 data-name [ other clauses ] [ IS ] EXTERNAL .
FD file-name [ IS ] GLOBAL ...

    What it does

    Normally each program's WORKING-STORAGE is private: no other program can see it, and the only way to share data is to pass it on a CALL with USING. GLOBAL and EXTERNAL are two other ways to share. Both go on an 01 item (and apply to everything inside it).

    GLOBAL

    A program can contain other programs, written before its END PROGRAM line. These are nested (or contained) programs; see Program structure. An item marked GLOBAL in the outer program can be used by name in every program nested inside it, without being declared again or passed on the CALL. All of them work on the same storage.

    Items without GLOBAL stay private to the program that declares them. If a nested program declares an item with the same name, its own item is the one it sees.

    A file's FD can be GLOBAL too, so nested programs can READ and WRITE a file the outer program opened, and a USE GLOBAL declarative can handle their I/O errors (see USE).

    EXTERNAL

    EXTERNAL is meant for programs compiled separately, which can't see each other's names. Each program declares the same 01 item with EXTERNAL, and they all share one copy of it, found by its name when the program starts. Declare it with the same name and the same layout in every program; the name is what links them, so a different layout would just read the same bytes a different way. Give the shared data its starting values with MOVE in the program that runs first, as the example does.

    Example: GLOBAL

    ADD-SALE is nested inside GLOBAL1. It adds to GRAND-TOTAL by name, although GRAND-TOTAL is declared only in the outer program and is not passed on the CALL. The sale amount itself is passed with USING, the usual way. After two calls, the outer program sees the total that the nested program built up.

    Example: EXTERNAL

    TAKEORDER is a separate program (in GLOBAL2.sub\TAKEORDER.cbl), not nested in GLOBAL2, so GLOBAL could not reach it. Both programs declare SHARED-TOTALS as EXTERNAL, and nothing is passed on the CALL. The main program sets the starting values, TAKEORDER counts the orders and records the customer, and afterwards the main program sees what TAKEORDER stored, because there is only one SHARED-TOTALS.

    SP COBOL notes

    GLOBAL data, GLOBAL files, USE GLOBAL and EXTERNAL items work as in GnuCOBOL 3.2. The debugger's Watch window view of COBOL data leaves out EXTERNAL items.
