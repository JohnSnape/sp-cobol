    SP COBOL Language Reference

    Every statement and data clause SP COBOL supports, in plain English, each with a short program you can compile and run.

      SP COBOL turns standard COBOL into an ordinary .NET program. Its front end is GnuCOBOL 3.2's, so the language is GnuCOBOL's default dialect (close to COBOL 2014), and a test suite checks that its programs print the same output and write the same data files as GnuCOBOL 3.2 does. A few things work differently on purpose, to help people learning COBOL; the pages mark them, and Differences from GnuCOBOL lists them all. SP COBOL is a preview, and some things that work in GnuCOBOL don't work in it yet; the pages warn about them, and Known problems collects them with what to write instead.

      New to COBOL? Start with Reading this reference, then Source format and Program structure. After that, the pages for DISPLAY, MOVE, PICTURE, IF and PERFORM cover most of what a first program needs.

      Every example on these pages was compiled with SP COBOL and run, and the output shown under it is what it printed. Click an example's file name to download it.

      Getting started

      • Reading this referenceHow the syntax boxes, the examples and the common COBOL terms on these pages work.
      • Source formatWhere things go on a line of fixed-format COBOL: sequence numbers, the indicator column, areas A and B.
      • Program structureHow a COBOL program is built from divisions, sections, paragraphs, sentences and statements.

      Divisions

      • IDENTIFICATION DIVISIONName the program, and optionally mark it COMMON or INITIAL.
      • ENVIRONMENT DIVISIONDescribe the computer, special names, and the files a program uses.
      • DATA DIVISIONDescribe every piece of data the program uses, section by section.
      • PROCEDURE DIVISIONThe division that holds the program's code, and how control moves through it.

      Data description

      • Level numbersHow the numbers in front of data names build records out of groups and elementary items.
      • PICTUREDescribe what an elementary item holds and how big it is, symbol by symbol.
      • USAGEChoose how an item is stored in memory: as characters, binary, packed decimal or floating point.
      • VALUEGive a data item the value it starts with when the program begins.
      • OCCURSRepeat an item to make a table (an array), with fixed or variable size.
      • REDEFINESDescribe the same bytes of storage a second way.
      • RENAMESLevel 66: give one name to a run of neighboring items in a record.
      • Condition-names (level 88)Give a name to a value or set of values, then test it like a true/false condition.
      • Constants (level 78 and CONSTANT)Give a name to a fixed value that the compiler substitutes wherever you use it.
      • JUSTIFIEDLine text up on the right of an alphanumeric item instead of the left.
      • BLANK WHEN ZEROShow a numeric display field as all spaces when its value is zero.
      • SIGNChoose where the sign of a signed DISPLAY number is kept, and whether it gets its own byte.
      • SYNCHRONIZEDLine binary items up on memory boundaries, adding unused bytes in front of them.
      • GLOBAL and EXTERNALShare data with nested programs (GLOBAL) or between separately compiled programs (EXTERNAL).
      • National data (PIC N)Hold Unicode text as UTF-16 characters with PIC N, N"..." literals and USAGE NATIONAL.

      Using data

      • LiteralsValues written directly in the program: numbers, quoted text, hexadecimal and other forms.
      • Figurative constantsReserved words such as ZERO, SPACES and HIGH-VALUES that stand for a value and fill a whole field.
      • Referring to dataName the exact data you mean: qualification with OF/IN, subscripts, indexes and reference modification.
      • ConditionsThe tests that IF, EVALUATE, PERFORM UNTIL and SEARCH WHEN use: relations, classes, signs, condition names, AND/OR/NOT.
      • Arithmetic expressionsFormulas built from numbers, data items and the operators + - * / **, as used in COMPUTE.

      Statements

      • ACCEPTRead a line of input, or get the date, the time, a command-line argument or an environment variable.
      • ADDAdd numbers together and store the sum.
      • ALTERChange where a GO TO jumps, while the program runs. Obsolete; SP COBOL can't build it at present.
      • CALLRun another COBOL program as a subprogram, passing it data, and come back.
      • CANCELReset a called program, so that the next CALL starts it with fresh WORKING-STORAGE.
      • CLOSEFinish with one or more files, writing out anything still waiting.
      • COMPUTEWork out an arithmetic expression and store the result.
      • CONTINUEA statement that does nothing, for places where COBOL needs a statement but you have nothing to do.
      • DELETERemove a record from a relative or indexed file, or delete a whole file.
      • DISPLAYPrint literals and data items on the screen (standard output), or send them elsewhere with UPON.
      • DIVIDEDivide one number by another, optionally keeping the remainder.
      • EVALUATEChoose one of several actions by comparing values or testing conditions; COBOL's case statement.
      • EXITLeave a paragraph, a section, a PERFORM loop or a called program early; or mark the end of a PERFORM THRU range.
      • GENERATEPrint a Report Writer detail line, with any headings, footings and page breaks it triggers.
      • GO TOJump to another paragraph or section, without coming back.
      • GOBACKEnd the current program: return to the caller from a subprogram, or end the run from the main program.
      • IFRun statements only when a condition is true, with an optional ELSE for when it is false.
      • INITIALIZEReset the fields of a group, record or table: spaces in text fields, zeros in numeric ones.
      • INITIATEStart a Report Writer report, resetting its page and line counters and its totals.
      • INSPECTCount, replace or convert characters inside a field.
      • JSON GENERATETurn a group item and its fields into JSON text.
      • MERGECombine files that are already in key order into one file in that order.
      • MOVECopy a value into one or more fields, converting it to fit each one.
      • MULTIPLYMultiply two numbers and store the product.
      • OPENOpen one or more files for reading, writing, updating or adding to the end.
      • PERFORMRun a paragraph, a section or a block of statements, once or in a loop.
      • READGet the next record of a file, or the record with a given key.
      • RELEASEHand a record to a SORT from inside its INPUT PROCEDURE.
      • RETURNTake the next sorted or merged record inside an OUTPUT PROCEDURE.
      • REWRITEReplace a record that is already in a file with a changed version.
      • SEARCHLook through a table for an entry that meets a condition.
      • SETSet or move a table index, turn on a condition name, or point a LINKAGE item at data.
      • SORTPut the records of a file, or the entries of a table, in order by one or more keys.
      • STARTPosition a relative or indexed file so the next READ NEXT begins at a chosen key.
      • STOPEnd the program, optionally with an exit code for whatever started it.
      • STRINGJoin pieces of text together into one field.
      • SUBTRACTSubtract one or more numbers from a field and store the difference.
      • SUPPRESSStop one Report Writer group from printing, from inside a USE BEFORE REPORTING declarative.
      • TERMINATEFinish a Report Writer report, printing its last footings and final totals.
      • UNSTRINGSplit text into separate fields at the delimiters you name.
      • USEName a section in DECLARATIVES that runs automatically when a file operation fails.
      • WRITEAdd a record to a file, with line spacing for printed reports.
      • XML GENERATETurn a group item and its fields into XML text.
      • XML PARSERead XML text event by event. Not supported: the compiler refuses it.

      Compiler directives

      • COPYBring the text of a copybook into the program as it is compiled.
      • REPLACEReplace pieces of text throughout the source, until REPLACE OFF.
