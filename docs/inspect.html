    Statements

    INSPECT

    Count, replace or convert characters inside a field.

    Syntax

    Format 1: count
INSPECT identifier-1 TALLYING
    { identifier-2 FOR { CHARACTERS [ phrase ] ...
                       | { ALL | LEADING | TRAILING } { identifier-3 | literal-1 } [ phrase ] ... } ... } ...

Format 2: replace
INSPECT identifier-1 REPLACING
    { CHARACTERS BY { identifier-4 | literal-2 } [ phrase ] ...
    | { ALL | LEADING | FIRST | TRAILING }
          { { identifier-3 | literal-1 } BY { identifier-4 | literal-2 } [ phrase ] ... } ... } ...

Format 3: count, then replace
INSPECT identifier-1 TALLYING ... REPLACING ...

Format 4: convert character by character
INSPECT identifier-1 CONVERTING { identifier-5 | literal-3 }
    TO { identifier-6 | literal-4 } [ phrase ] ...

where phrase is:
    { BEFORE | AFTER } INITIAL { identifier-7 | literal-5 }

    What it does

    INSPECT looks through the characters of identifier-1 from left to right. It can count what it finds (TALLYING), change what it finds (REPLACING), or swap characters one for one (CONVERTING).

    TALLYING

    Each FOR phrase adds to a counter, identifier-2, which must be a numeric item. INSPECT adds to the counter; it doesn't clear it first, so set it to zero yourself before the INSPECT.

    • CHARACTERS counts every character (inside the BEFORE/AFTER region, if you give one).
    • ALL "x" counts every place the text appears.
    • LEADING "x" counts the text only where it repeats right at the start of the field (or the region).
    • TRAILING "x" counts it where it repeats at the very end. This is a GnuCOBOL extension, and handy for counting the trailing spaces of a field.

    REPLACING

    Each phrase says what to look for and what to put in its place. The replacement must be the same length as the text it replaces, because INSPECT never changes the length of the field. CHARACTERS BY "x" replaces every character, ALL every match, LEADING the matches at the start, FIRST only the first match, and TRAILING (an extension) the matches at the end.

    With both TALLYING and REPLACING in one statement, the counting is done first, on the original text, and then the replacing.

    CONVERTING

    CONVERTING "abc" TO "xyz" changes every a to x, every b to y and every c to z, in one pass. The two strings must be the same length. It is the usual way to change letters to upper case (see also FUNCTION UPPER-CASE).

    BEFORE and AFTER INITIAL

    A phrase can be limited to part of the field. BEFORE INITIAL "," means "only look at the characters in front of the first comma"; AFTER INITIAL ":" means "only look at the characters after the first colon". If the comma or colon isn't there at all, BEFORE covers the whole field and AFTER covers nothing. You may give both, one BEFORE and one AFTER, on the same phrase.

    When phrases compete

    With several phrases in one INSPECT, it helps to know exactly how the scan works:

    • INSPECT moves along the field one position at a time. At each position it tries the phrases in the order you wrote them. The first phrase that matches there wins: it counts or replaces, and the scan jumps past the characters it matched. Later phrases never see those characters.
    • So the order matters. Counting ALL "AB" before ALL "A" gives different numbers from the other way round (the second example shows this).
    • Replaced characters are not looked at again: replacing X by B and then B by Y doesn't turn an X into a Y.
    • BEFORE and AFTER look for their delimiter in the text as it was before the INSPECT began, so replacing can't move the region's edge.

    The text is ABAABA plus four spaces. When "AB" is listed first, the A's that start an AB are counted as AB and skipped, so each counter gets 2. With "A" first, every A is taken by that phrase and AB never matches. In the third INSPECT both phrases add to the same counter: 4 A's plus 6 other characters is 10, every character counted exactly once. The X's become B's, but the B's made that way are not turned into Y's; only the original B is. In the last one the four A's in front of the colon become colons, and the region still ends at the original colon.

    SP COBOL notes

    SP COBOL's INSPECT follows GnuCOBOL's own algorithm step for step, so programs that depend on the finer points (competing phrases, regions, a signed number field, which is inspected without its sign) give the same results as GnuCOBOL 3.2.
