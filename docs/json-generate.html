    JSON GENERATE

    Turn a group item and its fields into JSON text.

    Syntax

    JSON GENERATE identifier-1 FROM identifier-2
    [ COUNT IN identifier-3 ]
    [ NAME OF { identifier-4 IS { literal-1 | OMITTED } } ... ]
    [ SUPPRESS identifier-5 ... ]
    [ ON EXCEPTION imperative-statement-1 ]
    [ NOT ON EXCEPTION imperative-statement-2 ]
[ END-JSON ]

    What it does

    JSON (JavaScript Object Notation) is the text format most web services use to exchange data. It looks like {"name":"value","count":42}. JSON GENERATE takes the data item after FROM, usually a group, and writes it as JSON into the alphanumeric field identifier-1.

    How the data becomes JSON

    • A group becomes an object, {"GROUP-NAME":{...}}, with one member per item inside it, in order. Groups inside it become objects inside the object.
    • The member names are the COBOL data names, exactly as written (upper case, with hyphens).
    • Numeric items become JSON numbers: leading zeros are dropped, the sign and decimal point are shown (00042 becomes 42, -123.45 stays as it is).
    • Alphanumeric items become JSON strings, with trailing spaces removed. A field of all spaces becomes a string of one space. Quotes and backslashes are escaped (\").
    • FILLER items are left out.

    The JSON text goes at the start of the output field, and is usually shorter than the field. Use COUNT IN to get that length, and refer to JSON-OUT (1:LEN) to use just the JSON.

    NAME OF and SUPPRESS

    NAME OF CUST-ID IS "id" uses a name of your choosing instead of the COBOL name, which matters when the receiving program expects lower-case names. NAME OF CUSTOMER IS OMITTED, for the group after FROM, leaves out the outer wrapper so the result is just {"id":42,...}.

    SUPPRESS CITY ACTIVE leaves those items out of the output.

    JSON-CODE and ON EXCEPTION

    After the statement, the special register JSON-CODE is zero if all went well. If the output field is too small, JSON-CODE is set to 1, the field holds as much of the text as fit, and the ON EXCEPTION statements run. NOT ON EXCEPTION runs when the statement succeeded.

    Example

    The first JSON GENERATE writes the whole CUSTOMER group: CUST-ID loses its leading zeros, the quotes inside the name are escaped, CITY (all spaces) becomes " " and the FILLER is skipped. The second renames two members, omits the outer CUSTOMER wrapper and suppresses CITY and ACTIVE. The third writes into a 20-character field, which is too small, so JSON-CODE is 1 and the field holds the first 20 characters.

    SP COBOL notes

    SP COBOL writes JSON itself, so no extra library has to be installed (GnuCOBOL uses the cJSON library for this). The text is the same as GnuCOBOL 3.2 produces, character for character.

    A table (an item with OCCURS) is not written as a JSON array: only its first entry is generated, as a single object. The compiler warns that this is "not implemented". This is GnuCOBOL 3.2's behavior, kept so that results match. If you need an array, build that part of the text yourself with STRING.
