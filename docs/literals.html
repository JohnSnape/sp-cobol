    Using data

    Literals

    Values written directly in the program: numbers, quoted text, hexadecimal and other forms.

    Syntax

    Numeric literal:
[ + | - ] digits [ . digits ]
[ + | - ] digits [ . digits ] E [ + | - ] digits      (floating-point)

Alphanumeric literal:
"characters"   or   'characters'

Other forms:
X"hex-digits"       alphanumeric, given as hexadecimal bytes
Z"characters"       alphanumeric, with a null byte added at the end
N"characters"       national (Unicode)
B"bits"             boolean

Joining literals:
literal-1 & literal-2 ...

    What it does

    A literal is a value written straight into the source, such as 100 or "TOTAL:", as opposed to a data item whose value can change.

    Numeric literals

    Digits, with an optional sign in front and an optional decimal point: 42, -0.5, +7, 12345.67. A numeric literal may have up to 38 digits. Don't put a comma or a space inside one, and don't end it with a decimal point (5. reads as 5 followed by the end of the sentence). A literal with E and an exponent, such as 1.5E3 (1500), is a floating-point literal.

    Alphanumeric literals

    Characters between quotation marks: "HELLO". Apostrophes work too: 'HELLO'. To put the quote character itself inside a literal, write it twice: "SHE SAID ""HI""" holds SHE SAID "HI". Inside apostrophes a quotation mark is ordinary, and the other way round.

    When a literal is moved to a longer field, it is padded with spaces on the right; when it is compared with a longer field, it is treated as if padded with spaces. A literal that won't fit on one line can be continued (see source format), but joining shorter literals with & is easier to read and to edit: "FIRST PART " & "SECOND PART" is one literal.

    Hexadecimal literals

    X"..." gives the bytes in hexadecimal, two digits per byte. X"41" is the letter A; X"0D0A" is a carriage return and line feed. Use it for bytes you can't type.

    Null-terminated literals

    Z"ABC" is the three letters followed by a byte of zero (LOW-VALUE), so it is four bytes long. This is the form C functions expect for a string.

    National literals

    N"..." is a national literal, for PIC N items: each character takes two bytes (UTF-16). MOVE N"ABC" TO NAT-NAME fills a PIC N(3) item, which is 3 characters and 6 bytes long. See national data.

    Boolean literals

    B"1" and B"0" are boolean literals, for items with PIC 1.

    Example: numbers and text

    Each numeric literal is moved to AMOUNT and shown through an edited picture. The doubled quotes in the first DISPLAY print as single ones. X"434F424F4C" is the five bytes C, O, B, O, L. The last DISPLAY shows one literal built from three with &.

    Example: the special forms

    Z"ABC" is 4 bytes, and moving it to C-TEXT leaves a LOW-VALUE byte in the fourth position. FLAG starts as B"1". 1.5E3 is 1500.

    SP COBOL notes

    The compiler marks national literals and PIC N as "unfinished" in GnuCOBOL 3.2 (warning -Wunfinished). SP COBOL implements them, and its build turns that warning off. DISPLAY of a PIC N item differs from stock GnuCOBOL: SP COBOL shows the characters. See national data.
