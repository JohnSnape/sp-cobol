    Statements

    MERGE

    Combine files that are already in key order into one file in that order.

    Syntax

    MERGE sort-file-name
    { ON { ASCENDING | DESCENDING } KEY data-name-1 ... } ...
    [ COLLATING SEQUENCE IS alphabet-name ]
    USING file-name-1 file-name-2 ...
    { GIVING file-name-3 ... | OUTPUT PROCEDURE IS procedure-1 [ { THRU | THROUGH } procedure-2 ] }

    What it does

    MERGE takes two or more files whose records are each already in order by the same keys, and combines them into one stream in that order. Think of two sorted piles of cards dealt into one sorted pile.

    It works like SORT: you need a sort file described with SD, whose record holds the key fields, and the KEY phrases name them. The USING files are opened, read and closed by MERGE, and must not be open. There is no INPUT PROCEDURE: the input always comes from the USING files.

    The result goes either to a file (GIVING), or to an OUTPUT PROCEDURE that fetches the records one at a time with RETURN.

    When records in different files have equal keys, the one from the file named first in USING comes first.

    Each input file must already be in order by the merge keys; sort it first if it isn't.

    Examples

    Monday's and Tuesday's files are each in account order. The merged file is too. Account A100 appears in both; Monday's record comes first because MONDAY-F is named first.

    The output procedure RETURNs the merged sales in date order and prints a total each time the date changes, plus one for the last date.

    SP COBOL notes

    COLLATING SEQUENCE doesn't work in SP COBOL yet; see SORT.
