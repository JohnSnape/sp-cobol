    Statements

    MULTIPLY

    Multiply two numbers and store the product.

    Syntax

    Format 1: multiply each receiving field in place
MULTIPLY { identifier-1 | literal-1 } BY { identifier-2 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-MULTIPLY ]

Format 2: store the product somewhere else
MULTIPLY { identifier-1 | literal-1 } BY { identifier-2 | literal-2 }
    GIVING { identifier-3 [ ROUNDED ] } ...
    [ ON SIZE ERROR imperative-statement-1 ]
    [ NOT ON SIZE ERROR imperative-statement-2 ]
[ END-MULTIPLY ]

    What it does

    Format 1 multiplies each field after BY by the first value and stores the answer back in that field. MULTIPLY 2 BY N means "N = 2 × N".

    Format 2 multiplies the two values and puts the product in every field after GIVING. The two values don't change. MULTIPLY PRICE BY QTY GIVING TOTAL means "TOTAL = PRICE × QTY". A GIVING field only receives the answer, so it may be a numeric-edited field such as PIC $$,$$9.99.

    Decimals and rounding

    The product can have more decimal places than either value (0.25 × 0.5 = 0.125). If the receiving field has fewer decimal places, the extra digits are dropped, unless you write ROUNDED after that field. Each field gets its own choice: one may be rounded and the next truncated.

    SIZE ERROR

    If the product has more digits in front of the decimal point than the receiving field can hold, that is a size error. Without ON SIZE ERROR, the high-order digits are lost silently. With it, the receiving field keeps its old value and your statements run instead. NOT ON SIZE ERROR runs when the answer fit. Use END-MULTIPLY when the statement sits inside an IF or another statement.

    Example

    12.99 × 3 is stored twice, once in a plain numeric field and once in an edited one. 38.97 × 0.0725 is 2.825325: TAX is rounded to 2.83 while TAX-CUT is cut to 2.82. 25 × 10 = 250 doesn't fit in PIC 99, so TINY keeps 25 and the SIZE ERROR message shows. 25 × 7 = 175 without a SIZE ERROR phrase keeps only the last two digits, 75. The last two statements use Format 1 (MULTIPLY 10 BY TINY), so the answer goes back into TINY itself.
