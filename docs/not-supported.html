    Not supported Not supported

    COBOL features SP COBOL does not support, and what to write instead.

    SP COBOL compiles the same language as GnuCOBOL 3.2. The first part of this page lists what it doesn't support, mostly because GnuCOBOL 3.2 doesn't either, and says what to do instead. The second part, Known problems, lists things that work in GnuCOBOL 3.2 but not yet in SP COBOL, a preview release.

    Calling programs

    PROCEDURE DIVISION RETURNING: a called program can't return a value this way. The compiler warns "program RETURNING is not implemented", as GnuCOBOL 3.2 does. Instead, pass the result back in an argument passed BY REFERENCE, or a status number in RETURN-CODE; the caller can copy RETURN-CODE into a field with CALL ... RETURNING field. See the example below.
    CALL ... RETURNING ADDRESS OF, program pointers (SET proc-pointer TO ENTRY "name" and calling through one), and CALL STATIC are not done. Call programs by name with CALL "NAME" or CALL identifier, where the identifier holds the name; see CALL.

    XML and JSON

    XML PARSE is a compile error: "XML PARSE is not implemented (GnuCOBOL 3.2 doesn't implement it either)". Read XML text with UNSTRING and INSPECT, or in a C# part of the project. See XML PARSE.
    Tables in XML GENERATE and JSON GENERATE: only the first occurrence of an OCCURS item is written (the compiler warns "not implemented"). Generate one occurrence at a time from a group that holds a single copy, or build the text with STRING.
    COMP-1 and COMP-2 items in XML GENERATE and JSON GENERATE stop the program. MOVE the value to a DISPLAY item (such as PIC -9(7).9(4)) and generate from that instead.

    Intrinsic functions

    BASECONVERT, BOOLEAN-OF-INTEGER, CHAR-NATIONAL, CONVERT, DISPLAY-OF, EXCEPTION-FILE-N, EXCEPTION-LOCATION-N, FIND-STRING, INTEGER-OF-BOOLEAN, MODULE-NAME, NATIONAL-OF and STANDARD-COMPARE are not implemented: the compiler stops with "FUNCTION 'name' is not implemented". Use EXCEPTION-FILE and EXCEPTION-LOCATION in place of the -N forms, INSPECT in place of FIND-STRING, and a MOVE between PIC X and PIC N items in place of DISPLAY-OF and NATIONAL-OF. Among the functions that do work, EXCEPTION-STATEMENT always returns spaces and CONTENT-OF treats every pointer as NULL. See Intrinsic functions.

    Debugging and reports

    USE FOR DEBUGGING declaratives, and so DEBUG-ITEM, make the program fail to build. Use debugging lines (D in column 7) with DISPLAY; see Debugging.
    CODE IS in a Report Writer RD makes the program fail to build (in GnuCOBOL 3.2 it produces an empty report). Leave it out; to tell several reports apart, give each its own file. See Report Writer.

    Screens

    The screen attributes LOWLIGHT, BLINK, BELL and FULL are accepted but do nothing, and the TIMEOUT, SCROLL, SIZE, CONTROL and CURSOR phrases of ACCEPT/DISPLAY at a position are ignored. A numeric input field with an assumed decimal point (PIC 9(3)V99) doesn't store what is typed; use an edited picture such as PIC ZZ9.99 for the screen field. Laying out a screen in Visual Studio's Windows Forms designer is planned, not available: write the SCREEN SECTION. See SCREEN SECTION.

    Files

    INDEXED files work, but in SP COBOL's own file format, so they can't be read by GnuCOBOL programs (or the other way round). Sequential, line sequential and relative files are the same on disk in both. See Files.

    Example: returning a result without RETURNING

    The called program, NOTSUPS1, adds 8% tax. The price goes in BY CONTENT, so NOTSUPS1 can't change it, and the answer comes back in WS-WITH-TAX, passed BY REFERENCE: 80.00 plus 8% is 86.40. RETURN-CODE carries a status: 0 the first time. The second call's result doesn't fit in PIC 9(4)V99, so NOTSUPS1 sets RETURN-CODE to 8, and RETURNING WS-STATUS copies it into WS-STATUS.
