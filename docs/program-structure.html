    Getting started

    Program structure

    How a COBOL program is built from divisions, sections, paragraphs, sentences and statements.

    Syntax

    IDENTIFICATION DIVISION.
PROGRAM-ID. program-name.
[ ENVIRONMENT DIVISION.
    environment-entries ]
[ DATA DIVISION.
    data-entries ]
[ PROCEDURE DIVISION [ USING data-name-1 ... ].
    [ section-name SECTION. ]
    paragraph-name.
        statement-1 [ statement-2 ] ... .
    ... ]
[ nested-program ... ]
[ END PROGRAM program-name. ]

    What it does

    A COBOL program is a nest of named parts, from large to small:

    PartWhat it is
    divisionThe four main parts, always in this order: IDENTIFICATION (the program's name), ENVIRONMENT (the computer and the files), DATA (every data item) and PROCEDURE (the code). Only the IDENTIFICATION DIVISION is required; leave out any other division you don't need.
    sectionA named group inside a division. The ENVIRONMENT and DATA divisions have fixed sections (WORKING-STORAGE SECTION, ...). In the PROCEDURE DIVISION you name your own sections, or use none.
    paragraphIn the PROCEDURE DIVISION, a name followed by a period, starting in area A, and the code after it up to the next paragraph or section name. Paragraphs are what PERFORM and GO TO refer to.
    sentenceOne or more statements ended by a period.
    statementOne action, starting with a COBOL verb: MOVE, ADD, IF, ...

    The period

    In the PROCEDURE DIVISION, a period ends a sentence, and it also ends every statement that is still open, however deeply nested. That is the classic COBOL trap: a period inside an IF ends the IF there, and the lines after it run whether the condition was true or not. The safe modern style is to write one period at the end of each paragraph and none inside it, closing each statement with its scope terminator instead.

    Outside the PROCEDURE DIVISION, periods end each header and each entry (01 TOTAL PIC 9(5).) and are required.

    Scope terminators

    Statements that contain other statements, or that have phrases like ON SIZE ERROR or AT END, can be closed with a matching END- word: END-IF, END-PERFORM, END-EVALUATE, END-READ, END-ADD, END-COMPUTE, END-STRING, END-CALL and so on. The terminator shows exactly where the statement stops, so you can nest one IF inside another without periods.

    Several programs in one file

    A source file may hold more than one program. Each one starts with its own IDENTIFICATION DIVISION and ends with END PROGRAM name. A program placed before its outer program's END PROGRAM is a nested program: it belongs to the outer program and is called with CALL. A program placed after another's END PROGRAM is a separate program that happens to share the file. When a file has only one program, END PROGRAM is optional.

    Example: the parts of a program

    The PROCEDURE DIVISION has two sections. In MAIN-LOGIC, the first IF is closed by END-IF, so "AFTER END-IF" is shown no matter what. The second IF is ended by the period after DISPLAY "NOT SHOWN", so the next sentence runs as usual. PERFORM HELPERS runs the whole HELPERS section: both its paragraphs, so COUNT-UP adds 1 a fourth time and SAY-DONE speaks. STOP RUN ends the program before control could fall into HELPERS on its own.

    Example: programs in one file

    PROGSTR2IN sits inside PROGSTR2 (before END PROGRAM PROGSTR2), so it is a nested program. PROGSTR2NEXT comes after PROGSTR2's END PROGRAM, so it is a separate program in the same file. Both are reached with CALL and come back with GOBACK.
