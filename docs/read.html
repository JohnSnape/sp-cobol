    READ Differs from GnuCOBOL

    Get the next record of a file, or the record with a given key.

    Syntax

    Format 1: the next (or previous) record
READ file-name [ NEXT | PREVIOUS ] [ RECORD ] [ INTO identifier-1 ]
    [ AT END imperative-statement-1 ]
    [ NOT AT END imperative-statement-2 ]
[ END-READ ]

Format 2: the record with a given key (RELATIVE and INDEXED, random or dynamic access)
READ file-name [ RECORD ] [ INTO identifier-1 ]
    [ KEY IS data-name-1 ]
    [ INVALID KEY imperative-statement-3 ]
    [ NOT INVALID KEY imperative-statement-4 ]
[ END-READ ]

    What it does

    READ copies a record from the file into the file's record area (the 01 level under its FD). The file must be open INPUT or I-O.

    Reading in order

    For SEQUENTIAL and LINE SEQUENTIAL files, and for RELATIVE and INDEXED files with ACCESS SEQUENTIAL, a plain READ file gets the next record. With ACCESS DYNAMIC you must write READ file NEXT to read in order; plain READ there means a read by key.

    When there are no more records, the READ is "at end": the status is 10 and the statements after AT END run. Otherwise the NOT AT END statements run. The usual loop reads until a flag set by AT END says to stop. A READ after the end gives status 46, an error, so don't read again once you've hit the end.

    A RELATIVE file read in order skips empty slots, and puts the slot number it read in the RELATIVE KEY item. An INDEXED file is read in order of its key (the RECORD KEY, or the key the last START or keyed READ used).

    INTO

    READ file INTO WS-ITEM reads the record and then moves it to WS-ITEM, as a MOVE would. It's handy for keeping the record in WORKING-STORAGE, where it stays after the next READ or after CLOSE.

    Reading by key

    With random or dynamic access, put the key first and then READ:

    • RELATIVE: move the slot number to the RELATIVE KEY item.
    • INDEXED: move the value to the RECORD KEY field in the record. To read by an alternate key instead, move the value to that field and write KEY IS that field.

    If there is no such record, the status is 23 and the INVALID KEY statements run; otherwise NOT INVALID KEY runs. A keyed READ also sets the position, so a READ NEXT afterwards carries on from that record in key order.

    READ PREVIOUS

    READ file PREVIOUS (RELATIVE or INDEXED, dynamic access) goes one record backwards: to the record before the last one read, in key or slot order.

    A WRITE doesn't move the reading position. After OPEN, then a WRITE by key, a READ NEXT still starts at the first record of the file.

    Examples

    A read loop

    Each READ puts a line in the record area and copies it INTO SCORE-WS, where it is split into a name and points. After three records the fourth READ is at end, which sets NO-MORE and stops the loop.

    Reading a relative file by slot

    Slot 3 is empty, so the first READ takes the INVALID KEY branch with status 23. The read of slot 4 works. READ NEXT then carries on from slot 4 to slot 5 and sets SEAT-NO to 05. The last READ NEXT finds nothing after slot 5: AT END, status 10.

    Reading an indexed file by an alternate key

    The READ with KEY IS AUTHOR finds the first Austen book. Its status is 02: success, and the next record in AUTHOR order has the same author. READ NEXT then follows the AUTHOR key (PERSUASION, then HARD TIMES by Dickens), and READ PREVIOUS steps back to PERSUASION. The book 0009 doesn't exist: status 23. This example isn't compared with stock GnuCOBOL, whose reference build has no indexed file support.

    READ PREVIOUS on a relative file

    START and READ NEXT give seat 7. Each READ PREVIOUS then steps back one record: seat 5, then seat 2. After the file is opened again, the WRITE of seat 9 leaves the position at the start of the file, so READ NEXT gives seat 2 and then seat 5. GnuCOBOL 3.2 prints something else here (see the notes below).

    SP COBOL notes

    A READ after the end of the file is status 46 and counts as an error: if the file has a USE procedure, it runs even when the READ has an AT END phrase, as in GnuCOBOL.

    Differs from GnuCOBOL 3.2, on purpose. On a RELATIVE file SP COBOL follows the COBOL standard: READ PREVIOUS gives the record just before the last one read, and a WRITE doesn't move the reading position. GnuCOBOL 3.2 skips a record on READ PREVIOUS (seat 2 instead of seat 5 in the last example), and after a WRITE by key its READ NEXT is at end of file. See Differences from GnuCOBOL.

    A RELATIVE file read in order whose next slot number has more digits than the RELATIVE KEY item can hold gives status 14. The record is still read, and the key is set to 0, as in GnuCOBOL. See FILE STATUS codes for an example.
