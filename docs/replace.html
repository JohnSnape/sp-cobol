    Compiler directives

    REPLACE

    Replace pieces of text throughout the source, until REPLACE OFF.

    Syntax

    Format 1: start replacing
REPLACE { ==pseudo-text-1== BY ==pseudo-text-2== } ... .

Format 2: stop replacing
REPLACE OFF .

    What it does

    Like COPY, REPLACE is an instruction to the compiler, not a statement that runs. From the REPLACE onward, every place where the source text matches pseudo-text-1 is compiled as if you had written pseudo-text-2 there instead. It stays in force until REPLACE OFF, until another REPLACE (which takes over from the first), or to the end of the program.

    Pseudo-text is the text between == marks. It is matched as COBOL words, so extra spaces or a line break between words don't matter. The replacement can be several words, or a whole statement. Quoted literals and comments are not searched: a word inside quotes is never replaced.

    REPLACE can go anywhere a word can, including before the DATA DIVISION. Its period belongs to it, so a REPLACE in the middle of a paragraph does not end a sentence.

    Uses: a size used in several places (one change updates every OCCURS and loop limit), or a short name for a statement you type often. For a value with a name, a constant (level 78 or 01 ... CONSTANT AS) is usually clearer.

    Example

    The first REPLACE turns every TABLE-SIZE into 3, both in the OCCURS clause and in the PERFORM's UNTIL, and every SHOW-RULE into a DISPLAY of a dashed line. Inside the literal "TABLE-SIZE IS " nothing changes. The second REPLACE takes over: from there on, MESSAGE-TEXT means the literal "REPLACED TEXT". After REPLACE OFF, MESSAGE-TEXT is the data item again.

    SP COBOL notes

    REPLACE is handled by GnuCOBOL's own front end, so it behaves exactly as in GnuCOBOL 3.2.
