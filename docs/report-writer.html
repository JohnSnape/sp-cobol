    Report Writer Differs from GnuCOBOL

    Describe a printed report's layout once, then let COBOL handle headings, page breaks and totals.

    Most business programs end by printing something: a list with a heading on every page, subtotals when a department or region changes, and a grand total at the end. Writing that by hand means counting lines, remembering the previous value of a field and adding up totals yourself. The Report Writer does all of that for you. You describe what each kind of line looks like in the REPORT SECTION, and the PROCEDURE DIVISION needs only four statements: INITIATE, GENERATE, TERMINATE and, in a declarative, SUPPRESS.

    Syntax

    Format 1: name the report in the file's FD
FD file-name
    { REPORT IS | REPORTS ARE } report-name ...

Format 2: describe the report (DATA DIVISION, after WORKING-STORAGE)
REPORT SECTION.
RD report-name
    [ { CONTROL IS | CONTROLS ARE } [ FINAL ] identifier-1 ... ]
    [ PAGE [ LIMIT IS ] integer-1 [ LINES ]
        [ HEADING integer-2 ]
        [ FIRST DETAIL integer-3 ]
        [ LAST DETAIL integer-4 ]
        [ FOOTING integer-5 ] ] .

Format 3: a report group (level 01) and its lines (02-49)
01 [ group-name ] TYPE IS
        { REPORT HEADING | RH
        | PAGE HEADING | PH
        | CONTROL HEADING | CH  { identifier-1 | FINAL }
        | DETAIL | DE
        | CONTROL FOOTING | CF  { identifier-1 | FINAL }
        | PAGE FOOTING | PF
        | REPORT FOOTING | RF }
    [ NEXT GROUP IS { integer-6 | PLUS integer-7 | NEXT PAGE } ] .
   nn LINE NUMBER IS { integer-8 | PLUS integer-9 }
      [ PRESENT WHEN condition-1 ] .
      nn [ field-name ] COLUMN NUMBER IS [ LEFT | CENTER | RIGHT ] integer-10
         PICTURE IS picture-string
         { SOURCE IS identifier-2
         | VALUE IS literal-1
         | SUM identifier-3 ... [ RESET ON { identifier-4 | FINAL } ] }
         [ GROUP INDICATE ] .

Format 4: a procedure that runs just before a group prints
DECLARATIVES.
section-name SECTION.
    USE BEFORE REPORTING group-name.
paragraph-name.
    statements ...
END DECLARATIVES.

    What it does

    The pieces

    A report is written to a file, so you need a SELECT and an FD as for any output file (see Files). The FD has no record description. Instead it says REPORT IS report-name, and the layout goes in an RD (report description) entry in the REPORT SECTION. A LINE SEQUENTIAL file is the usual choice: each printed line becomes one line of a text file.

    In the PROCEDURE DIVISION you OPEN OUTPUT the file, INITIATE the report, GENERATE a detail line for each record, TERMINATE the report and CLOSE the file. Headings, footings, page breaks and totals happen automatically during GENERATE and TERMINATE.

    The RD entry

    • CONTROLS ARE lists the control fields, from the most important to the least. When the value of a control field changes between one GENERATE and the next, that's a control break: the footing for that field prints (with its subtotals), then the heading for the new value. A break in one field also counts as a break in every field listed after it. FINAL is a pretend control field that "breaks" only once, at TERMINATE, which is where grand totals go. Your data must already be in order by the control fields (see SORT).
    • PAGE LIMIT is the number of lines on a page. HEADING is the first line anything may print on, FIRST DETAIL the first line for detail and control groups, LAST DETAIL the last line for detail lines, and FOOTING the last line for control footings. When the next group won't fit, the page footing prints and a new page starts with the page heading.
    Always give a PAGE clause. Without one there are no pages, and line positions are not what you'd expect: in a test, LINE PLUS 2 left no blank line, and an unwanted blank line appeared inside the heading.

    Report groups

    Each 01 level in the RD is a report group, one or more lines that print together. Its TYPE says when it prints:

    TYPEPrints
    REPORT HEADINGonce, at the start of the report
    PAGE HEADINGat the top of every page
    CONTROL HEADING fieldbefore the first detail of each new value of the field
    DETAILeach time you GENERATE it
    CONTROL FOOTING fieldafter the last detail of each value of the field (subtotals)
    CONTROL FOOTING FINALonce, at TERMINATE (grand totals)
    PAGE FOOTINGat the bottom of every page
    REPORT FOOTINGonce, at TERMINATE, after everything else. In SP COBOL and GnuCOBOL it starts a new page.

    A group needs a name only if the program refers to it: a DETAIL you GENERATE, or a group named in USE BEFORE REPORTING.

    Lines and columns

    • LINE NUMBER IS 3 prints on line 3 of the page (absolute). LINE NUMBER IS PLUS 1 prints one line below the previous line (relative); PLUS 2 leaves one blank line.
    • NEXT GROUP on a group moves the position after the group prints: PLUS n skips n lines, NEXT PAGE forces a page break, and an integer moves to that line.
    • COLUMN 9 starts the field in column 9. COLUMN CENTER 20 centers it on column 20, and COLUMN RIGHT 40 makes it end in column 40. COLUMN LEFT is the same as plain COLUMN.
    • Every printed field has a PICTURE, usually an edited one such as Z,ZZ9.99 (see PICTURE).

    Where a field's value comes from

    • VALUE "text": fixed text, such as a column title.
    • SOURCE identifier: the field's current value, moved in when the group prints. PAGE-COUNTER and LINE-COUNTER are allowed here.
    • SUM identifier: a running total. Every GENERATE adds the identifier into the counter; when the footing prints, the counter is printed and reset to zero. Give the sum field a name and a higher footing can SUM that name: a sum of sums, as the grand total in the first example does. RESET ON FINAL (or RESET ON a higher control field) keeps the counter running across smaller breaks, which gives a cumulative total.
    SUM ... UPON detail-name is accepted, but in GnuCOBOL 3.2 and SP COBOL the counter still grows on every GENERATE of every detail, so don't rely on it.

    Printing only some of the time

    • GROUP INDICATE on a detail field prints it only on the first detail after a control break or a new page, so a region name isn't repeated on every line.
    • PRESENT WHEN condition on a LINE prints that line only when the condition is true. The second example uses it for a warning line.
    PRESENT WHEN on a single field (rather than a LINE) compiles, but GnuCOBOL 3.2 never prints such a field, whether the condition is true or not. SP COBOL keeps that behavior. Put the field on a line of its own and use PRESENT WHEN on the LINE, or move the text into a SOURCE field yourself.

    PAGE-COUNTER and LINE-COUNTER

    Each report has two counters, which you can DISPLAY or use as a SOURCE. PAGE-COUNTER is the page number (1 after INITIATE). LINE-COUNTER is the line last printed on the current page. With two reports, say which one: PAGE-COUNTER OF SALES-REPORT. See special registers.

    USE BEFORE REPORTING

    A section in the DECLARATIVES with USE BEFORE REPORTING group-name runs just before that group prints. It can change the fields the group's SOURCE clauses read, and it can stop the group from printing with SUPPRESS PRINTING. During a control footing, the control field still holds the old value (the one being totaled), so the declarative sees the group that is ending.

    SP COBOL notes

    SP COBOL's Report Writer is a step-by-step port of GnuCOBOL's own (libcob's reportio.c), so reports come out the same, line for line, as with GnuCOBOL 3.2. One exception is a bug fix:

    Differs from GnuCOBOL 3.2: when a DETAIL group has a USE BEFORE REPORTING declarative, stock GnuCOBOL 3.2 adds each detail into the SUM counters twice, so every total is doubled (the third example prints 563.00 there); it can also run control-heading declaratives again and print a page heading twice. SP COBOL adds each detail once and prints 287.75. Declaratives on headings and footings behave the same in both.
    Don't use CODE IS in the RD. The program builds, but GnuCOBOL 3.2 writes an empty report file when it is given, and SP COBOL does the same.

    A report file assigned with ASSIGN TO DISPLAY prints on the screen, including the blank lines that pad the last page, as in GnuCOBOL.

    Not checked against GnuCOBOL yet, so use with care: PAGE LIMIT and the other PAGE numbers given by data items instead of integers, OCCURS in report lines, PRESENT AFTER / ABSENT AFTER.
