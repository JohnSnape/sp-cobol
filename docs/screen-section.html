    SCREEN SECTION Differs from GnuCOBOL

    Lay out a full-screen form with labels, input fields and colors, then DISPLAY and ACCEPT it.

    A SCREEN SECTION describes a whole screen at once: where each label goes, which fields the user can type into, and their colors. DISPLAY screen-name draws it and ACCEPT screen-name lets the user fill it in, moving between fields with Tab, until they press Enter or a function key. In SP COBOL the same program runs as a DOS-style text screen in a console window, or as a real Windows window.

    Syntax

    Format 1: describe a screen (last section of the DATA DIVISION)
SCREEN SECTION.
01 screen-name [ attributes ] .
   nn [ item-name ]
      [ LINE NUMBER IS [ PLUS ] integer-1 ]
      [ { COLUMN | COL } NUMBER IS [ PLUS ] integer-2 ]
      { VALUE IS literal-1
      | { PICTURE | PIC } IS picture-string
          { USING identifier-1 | FROM { identifier-2 | literal-2 } | TO identifier-3 } ... }
      [ attributes ] .

attributes:
    BLANK SCREEN | BLANK LINE | ERASE { EOL | EOS }
    FOREGROUND-COLOR integer-3 | BACKGROUND-COLOR integer-4
    HIGHLIGHT | LOWLIGHT | REVERSE-VIDEO | UNDERLINE | BLINK
    SECURE | REQUIRED | AUTO | FULL | BELL

Format 2: show and fill in a screen
DISPLAY screen-name
ACCEPT screen-name

Format 3: one field at a position
DISPLAY { identifier-4 | literal-3 } LINE integer-5 { COLUMN | COL } integer-6
    [ WITH { BLANK SCREEN | BLANK LINE | ERASE { EOL | EOS } | HIGHLIGHT
           | REVERSE-VIDEO | UNDERLINE | FOREGROUND-COLOR integer-3
           | BACKGROUND-COLOR integer-4 } ... ]
ACCEPT identifier-5 LINE integer-5 { COLUMN | COL } integer-6
    [ WITH { AUTO | SECURE | REQUIRED | UPPER | LOWER | UPDATE | HIGHLIGHT ... } ... ]

Format 4: which key ended the ACCEPT, and where the cursor starts (ENVIRONMENT DIVISION)
SPECIAL-NAMES.
    [ CRT STATUS IS identifier-6 ]
    [ CURSOR IS identifier-7 ] .

    What it does

    Screen items

    Screen items are numbered like data items: an 01 for the whole screen, and 05 (or any higher level) for the parts. An item is one of three kinds:

    • a literal, VALUE "Name:": text that is shown and can't be changed;
    • a field, PIC X(20) USING CUST-NAME: a place on the screen tied to a WORKING-STORAGE item;
    • a group with no PIC or VALUE, which holds other items and passes its attributes (such as colors) down to them.

    A field's PIC sets how wide it is and how its value looks, so an edited picture such as ZZ,ZZ9.99 works on screens as it does in MOVE. Three words say which way the data goes:

    ClauseDISPLAY showsACCEPT stores what was typed into
    FROM itemthe item's valuenothing: the field is output only
    TO iteman empty fieldthe item
    USING itemthe item's valuethe same item

    Positions

    Lines are numbered from 1 at the top and columns from 1 at the left, on an 80 by 25 screen. LINE 3 COL 10 is an absolute position. LINE PLUS 2 is two lines below the previous item, and COL PLUS 2 starts two columns after the end of the previous item (so one blank column between them). An item with no LINE stays on the previous item's line, and one with no COL follows straight on after the previous item.

    Clearing

    • BLANK SCREEN clears the whole screen before the screen is drawn, in the colors given with it.
    • BLANK LINE clears the item's line first; ERASE EOL clears from the item to the end of its line; ERASE EOS from the item to the end of the screen.

    Colors and looks

    FOREGROUND-COLOR is the color of the characters and BACKGROUND-COLOR the color behind them. The numbers are the eight colors of the PC text screen:

    NumberColorNumberColor
    0black4red
    1blue5magenta
    2green6brown (yellow when HIGHLIGHT)
    3cyan7white (light gray)

    HIGHLIGHT uses the bright version of the foreground color, REVERSE-VIDEO swaps the foreground and background colors, and UNDERLINE underlines. LOWLIGHT, BLINK and BELL are accepted but have no visible effect in SP COBOL.

    Input fields

    • SECURE: what is typed shows as *, and the field is drawn empty afterwards. Use it for passwords.
    • REQUIRED: Enter is refused while this field is empty; the cursor goes to it with the message "Please fill in this field."
    • AUTO: when the field is full, the cursor moves on to the next field by itself (on the last field, the ACCEPT ends as if Enter was pressed).
    • FULL is accepted but not enforced by SP COBOL.

    While a screen is accepted the keys work like this: typing replaces or overwrites characters (Insert switches to inserting), Left/Right, Home/End, Backspace and Delete edit, Tab or Down goes to the next field, Shift+Tab or Up to the previous one. Fields are visited top to bottom, left to right. Enter, Esc, PgUp, PgDn and the function keys end the ACCEPT. Input fields show an underscore in each empty position.

    CRT STATUS: which key was pressed

    Name a 4-digit field in CRT STATUS IS (in SPECIAL-NAMES, see ENVIRONMENT DIVISION) and every ACCEPT puts there the key that ended it:

    KeyCode
    Enter0000
    F1 to F241001 to 1024
    Page Up / Page Down2001 / 2002
    Esc2005
    ACCEPT of a screen that has no input fields8000

    Without a CRT STATUS clause the code goes to the special register COB-CRT-STATUS (see special registers). Up and Down move between fields rather than ending the ACCEPT, so they don't return a code.

    CURSOR IS: where the ACCEPT starts

    Normally an ACCEPT of a screen starts in its first input field. Name a 4-digit field (line and column, LLCC) in CURSOR IS in SPECIAL-NAMES, and the ACCEPT starts in the input field at that position instead: with 0410 in it, the field at line 4, column 10. When the ACCEPT ends, the field holds the position of the input field the cursor was in.

    Single fields with LINE and COL

    Without a SCREEN SECTION you can still place things: DISPLAY "Age:" LINE 3 COL 1 shows a value at a position, and ACCEPT WS-AGE LINE 3 COL 8 reads one field there. Such an ACCEPT starts with an empty field; add WITH UPDATE to start from the item's current value. WITH UPPER or LOWER changes the case of letters as they are typed. Once the screen is in use, a plain DISPLAY (without LINE/COL) writes on the next line of the screen. See also ACCEPT and DISPLAY.

    One program, two kinds of screen

    SP COBOL draws the same SCREEN SECTION in two ways. The console version is a DOS-style text screen in a console window. The Windows version is a window with a grid of character cells, where the input fields are real text boxes. The program's logic is the same in both: ACCEPT waits until Enter or a function key, then returns with the fields filled in.

    A "COBOL Screen App" project has a ScreenMode property: Both (the default) builds NAME.exe (console) and NAME-Win.exe (window) from the one source; Console or Forms builds only one. When running, the environment variable COB_SCREEN=console or COB_SCREEN=forms picks the kind of screen.

    Examples

    These examples are run with keystrokes from a script; the boxes show the screen as it looked at each ACCEPT and when the program ended, and the lines under a box say which key ended that ACCEPT ([key 0] is Enter) and any message or beep. Colors are not shown.

    A data-entry screen

    The keys were Tab, Enter, "LONDON", Tab, "1234", Enter. The name field starts with "ADA LOVELACE" because of USING; Tab leaves it unchanged. The first Enter is refused, since City is REQUIRED and empty, so there is a beep, a message, and a second round of ACCEPT. The PIN shows as stars while typed and is blanked afterwards, but the program received 1234. "Customers so far:" comes from FROM: shown, never typed into. The last lines are single-field DISPLAYs with LINE and COL.

    Function keys and CRT STATUS

    The keys were F1, "12" Enter, F5, F3. Each ACCEPT puts the key code in WS-KEY (1001 for F1, 0 for Enter, 1005, 1003 for F3) and the EVALUATE picks a message, which the next DISPLAY shows. ERASE EOL clears the rest of line 5 each time.

    Single fields, and number checks

    The keys were "a42" Enter, "1.5" Enter, "-5" Enter, "7" Enter, "abc". The letter "a" is refused in a numeric field. "1.5" is refused because WS-QTY is PIC 9(3), whole numbers only, and "-5" because it has no sign; each time the cursor stays in the field. The 7 is shown as 007, the way PIC 9(3) shows it. The Code field is AUTO and UPPER, so "abc" becomes ABC and the ACCEPT ends when the third letter fills it.

    Starting in a chosen field, and an assumed decimal point

    The keys were "12.5" Enter. WS-CURSOR holds 0410, so the ACCEPT starts in the Price field on line 4, column 10, not in Item, and Item keeps PENCIL. The Price field has the same picture as WS-PRICE, 9(3)V99: it shows 1.25 as 00125, with no point, and the 12.5 typed is stored as 12.50. After the ACCEPT, WS-CURSOR holds 0410, the start of the field the cursor was in.

    SP COBOL notes

    Differs from GnuCOBOL 3.2, on purpose, to suit beginners (plain DISPLAY and ACCEPT without screens are not affected):
    • An item with no color given takes the colors of the last BLANK SCREEN, not the terminal's default colors.
    • The first key typed in a field replaces its old contents, like a Windows text box. GnuCOBOL overwrites in place. To edit the old value instead, press an arrow key, Home or End first.
    • Numeric fields are checked when you leave them, with plain-English messages ("This field holds whole numbers only."), and are shown again through their PICTURE.
    After an ACCEPT, the CURSOR IS field holds the start position of the input field the cursor was in. GnuCOBOL gets the exact column from its curses library, so there it can be a column inside the field, after what was typed.

    A numeric input field with an assumed decimal point (PIC 9(3)V99) shows no point, which is hard to read. An edited picture with a real point, such as PIC ZZ9.99 USING WS-PRICE, is friendlier.

    On ACCEPT ... LINE ... COL, the phrases for TIMEOUT, SCROLL, SIZE, CONTROL and CURSOR are accepted but ignored. JUSTIFIED and BLANK WHEN ZERO on screen items are accepted; JUSTIFIED RIGHT had no visible effect in a test.

    Screen examples can't be compared with stock GnuCOBOL, because the reference build has no screen support, so the screens above were checked by eye.
