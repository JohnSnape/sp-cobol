    Data description

    SIGN

    Choose where the sign of a signed DISPLAY number is kept, and whether it gets its own byte.

    Syntax

    [ SIGN [ IS ] ] { LEADING | TRAILING } [ SEPARATE [ CHARACTER ] ]

    What it does

    A signed number with usage DISPLAY (PIC S9(3)) keeps one character per digit. The S doesn't add a byte. Instead, the sign is folded into one of the digits by changing that character: this is called an overpunched sign, after the way punched cards marked it. The SIGN clause says where the sign goes.

    ClauseWhere the sign is-123 is stored asSize of S9(3)
    (none)folded into the last digit12s3
    SIGN LEADINGfolded into the first digitq233
    SIGN TRAILING SEPARATEits own byte after the digits123-4
    SIGN LEADING SEPARATEits own byte before the digits-1234

    In the overpunched forms, a negative 0-9 digit is stored as one of the letters p to y, which is what you see if you look at the bytes in a data file or through a PIC X view of the field. A positive number is stored as plain digits. A DISPLAY of the number itself always shows a readable sign, whatever the clause.

    SEPARATE costs one byte but makes data files easier to read and to exchange with other programs; CHARACTER is an optional word. The SIGN clause needs an S in the PICTURE.

    Example

    The first line DISPLAYs all four items. Three show -123; the TRAILING SEPARATE item is shown as it is stored, 123-, with the sign last. The next lines look at their bytes with reference modification, which treats them as plain characters: the default puts the sign in the last digit (3 becomes s), LEADING puts it in the first (1 becomes q), and the SEPARATE forms keep an ordinary - in a byte of its own, which is why they are 4 bytes long. +123 is stored as plain 123.

    See also

    PICTURE (the S symbol and edited signs + - CR DB), USAGE, Referring to data (reference modification).
