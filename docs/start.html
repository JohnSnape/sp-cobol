    Statements

    START

    Position a relative or indexed file so the next READ NEXT begins at a chosen key.

    Syntax

    START file-name
    [ KEY IS { EQUAL TO | = | GREATER THAN | > | NOT LESS THAN | NOT <
             | GREATER THAN OR EQUAL TO | >= | LESS THAN | <
             | NOT GREATER THAN | NOT > | LESS THAN OR EQUAL TO | <= }
          data-name-1 ]
    [ INVALID KEY imperative-statement-1 ]
    [ NOT INVALID KEY imperative-statement-2 ]
[ END-START ]

    What it does

    START doesn't read anything. It finds the first record that meets a condition on its key and makes it the current position, so the next READ ... NEXT returns that record and later ones follow in key order. Use it to browse a RELATIVE or INDEXED file from a point in the middle, such as "all customers from M on". The file must be open INPUT or I-O, with sequential or dynamic access.

    Set the key first, then START:

    • RELATIVE: the slot number in the RELATIVE KEY item; KEY IS names that item.
    • INDEXED: the value in the RECORD KEY field, or in an alternate key field. KEY IS names the field, and that key also becomes the order for the READ NEXTs that follow.

    Without a KEY phrase the condition is "equal to the RECORD KEY (or RELATIVE KEY)". >= and NOT < mean the same thing. With < or <= the position is the last record below (or at) the value.

    If no record meets the condition, the status is 23 and INVALID KEY runs.

    Examples

    Relative file

    There is no day 5, so KEY IS GREATER THAN OR EQUAL TO positions at day 8. KEY > DAY-NO with 8 positions at day 9. Day 3 exists, so the KEY = START succeeds. Nothing comes after day 9: status 23 and INVALID KEY. After a successful START and READ NEXT the RELATIVE KEY holds the slot number actually read.

    Indexed file, alternate key

    The START uses the alternate key DEPT, so the READ NEXTs that follow go in department order, from SALES on. The 02 status on Ava's record means the next record has the same department. This example isn't compared with stock GnuCOBOL, whose reference build has no indexed file support.
