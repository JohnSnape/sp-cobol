    Statements

    STOP

    End the program, optionally with an exit code for whatever started it.

    Syntax

    STOP RUN [ { RETURNING | GIVING } { identifier-1 | integer-1 } ]

STOP RUN WITH { ERROR | NORMAL } STATUS [ { identifier-1 | integer-1 } ]

Obsolete:
STOP literal-1

    What it does

    STOP RUN ends the whole program at once. Files that are still open are closed, and control goes back to whatever started the program: the command prompt, a batch file, or Visual Studio. Statements after STOP RUN never run. It doesn't matter whether STOP RUN is in the main program or in a program reached by CALL: the whole run ends. To end only a called program and return to its caller, use GOBACK.

    The exit code

    Every program hands a number back to the operating system when it ends, its exit code. Zero means "all went well"; other values usually mean some kind of problem. A batch file can test it with IF ERRORLEVEL, and PowerShell shows it in $LASTEXITCODE.

    In COBOL the exit code comes from the special register RETURN-CODE, which starts at zero. Move a number into it before STOP RUN and that number becomes the exit code. (RETURN-CODE is also how a called program passes a status back to its caller; see special registers.)

    STOP RUN RETURNING 4 (or GIVING 4) sets the exit code in the same statement. STOP RUN WITH ERROR STATUS 2 does the same thing in the wording of the 2014 standard, and WITH NORMAL STATUS ends with zero.

    STOP literal

    Old programs sometimes contain STOP "MOUNT TAPE 2". It shows the message to the operator, waits for Enter, and then carries on with the next statement: the program does not end. It is obsolete; use DISPLAY followed by ACCEPT to pause for the user instead, which also lets you read what was typed.

    Examples

    The program finds three errors, puts 8 into RETURN-CODE and stops. Its exit code is 8; run from a command prompt, echo %ERRORLEVEL% afterwards would show 8. The last DISPLAY never runs.
