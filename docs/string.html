    Statements

    STRING

    Join pieces of text together into one field.

    Syntax

    STRING { { identifier-1 | literal-1 } ...
         DELIMITED BY { identifier-2 | literal-2 | SIZE } } ...
    INTO identifier-3
    [ WITH POINTER identifier-4 ]
    [ ON OVERFLOW imperative-statement-1 ]
    [ NOT ON OVERFLOW imperative-statement-2 ]
[ END-STRING ]

    What it does

    STRING copies several pieces of text, one after another, into the field after INTO. It is how you build a full name from a first and a last name, or a line of output from several fields, without the extra spaces that each fixed-length field carries.

    DELIMITED BY

    Each piece (or group of pieces) is followed by DELIMITED BY, which says how much of it to copy:

    • DELIMITED BY SIZE copies the whole piece, trailing spaces included.
    • DELIMITED BY SPACE copies up to, but not including, the first space. This is the usual way to drop the padding at the end of a name, though it also stops at a space in the middle ("SAN DIEGO" gives just "SAN").
    • DELIMITED BY "," or by a field copies up to the first appearance of that text. If the text isn't there, the whole piece is copied.

    One DELIMITED BY phrase applies to all the pieces written in front of it, back to the previous DELIMITED BY.

    The receiving field

    STRING only writes the characters it copies. It doesn't pad the rest of the receiving field with spaces, so whatever was there before stays there. That is why the examples MOVE SPACES to the field first.

    WITH POINTER

    The pointer is a numeric field holding the position in the receiving field where the next character will go. Set it before the STRING (to 1 to start at the beginning); STRING starts there and, when it finishes, leaves the pointer just past the last character written. That lets you add to a field in several steps. Without a pointer, STRING starts at position 1.

    OVERFLOW

    If the receiving field fills up before all the text is copied, the rest is dropped and the ON OVERFLOW statements run. The characters that did fit stay in the field. Overflow also happens if the pointer starts out less than 1 or past the end of the field; then nothing is copied. NOT ON OVERFLOW runs when everything fit.

    Example

    The full name is built from the first name up to its first space, one space, and the last name up to its first space. In the second STRING, the comma delimiter applies to both "CITY=" and CITY, so the city is copied only up to its comma. With the pointer set to 4, ABCDEF goes into positions 4 to 9 of a field of periods and the pointer ends at 10. "ADA" plus seven spaces plus "LOVELACE" is too long for 8 characters, so only the first eight are kept and ON OVERFLOW runs; the last STRING fits.

    SP COBOL notes

    In this preview, a pointer that starts out of range (0, or past the end of the receiving field) does not raise ON OVERFLOW as it does in GnuCOBOL 3.2. Check the pointer yourself before the STRING if it might be out of range.
