    Statements

    USE

    Name a section in DECLARATIVES that runs automatically when a file operation fails.

    Syntax

    PROCEDURE DIVISION.
DECLARATIVES.
section-name SECTION.
    USE [ GLOBAL ] AFTER STANDARD { EXCEPTION | ERROR } PROCEDURE
        ON { file-name-1 ... | INPUT | OUTPUT | I-O | EXTEND } .
paragraph-name.
    statements ...
[ another section with its own USE ] ...
END DECLARATIVES.
section-name-2 SECTION.
    the rest of the program ...

    What it does

    A USE statement turns a section into an error procedure for files. You don't PERFORM it yourself: the runtime runs it right after a file statement fails, and then the program carries on with the statement after the one that failed. Inside the procedure the file's FILE STATUS item already holds the code, so the procedure can report it, count it or set a flag.

    All USE sections go at the very start of the PROCEDURE DIVISION, between DECLARATIVES. and END DECLARATIVES. Each one is a section whose first sentence is the USE statement. After END DECLARATIVES the program proper must start with a section header.

    ERROR and EXCEPTION mean the same; STANDARD is optional.

    Which files it covers

    • ON file-name: errors on those files.
    • ON INPUT, ON OUTPUT, ON I-O, ON EXTEND: errors on any file open in that mode (that has no procedure of its own).

    A procedure for a particular file is used for that file in place of an open-mode procedure.

    When it runs

    • For errors (status 30 and up, and 46 / 47 / 48 / 49 and the like).
    • For end of file (10) and key problems (2x), but only when the statement has no AT END or INVALID KEY phrase. With the phrase, the phrase runs instead.
    • A READ after end of file (46) is an error, so the procedure runs even when that READ has an AT END phrase, and the AT END statements don't.

    A file with a USE procedure doesn't stop the program on errors, even with no FILE STATUS clause. Use that with care: if the procedure only prints a message, the program goes on as if nothing happened.

    USE GLOBAL

    In a program that contains nested programs, USE GLOBAL makes the procedure cover errors in the nested programs too: on a GLOBAL file they use, or on their own files by open mode. The procedure runs in the outer program and control then goes back to the nested program.

    Two other kinds of USE exist: USE BEFORE REPORTING, part of the Report Writer, and USE FOR DEBUGGING, described with debugging. Its procedures run only when the environment variable COB_SET_DEBUG=Y is set, as in GnuCOBOL.

    Examples

    OPEN INPUT of the missing config.dat runs CONFIG-PROBLEM, which has the status 35, and the program goes on. CONFIG was open for input too, but only its own procedure runs. The second READ of ORDERS hits the end and has no AT END phrase, so INPUT-PROBLEM runs with status 10. The third READ is past the end: status 46, an error, so INPUT-PROBLEM runs again and the AT END phrase doesn't.

    The nested program USE2LOAD opens the GLOBAL file HISTORY, which doesn't exist. The outer program's USE GLOBAL procedure handles it, then USE2LOAD continues and sees the 35 itself.
